## 1. 最终要回答的问题

本项目研究：当输入是数学公式、输出是定点 RTL 时，搜索系统应使用什么评价信号，才能识别
不同硬件结构之间真正有意义的数值质量差异，并找到更好的质量—成本折中。

当前 working thesis 的因果链是：

```text
Boolean verdict 聚合丢失误差幅值信息
                    ↓
structure-aware 解析数值适应度补回排序信号
                    ↓
检验该信号是否提高 LLM 结构提议的相对价值
                    ↓
在完整通信子链与真实综合 PPA 上验证决策后果
```

论文主张分为四层：

1. **问题命题**：单阈值 verdict 或通过率一般不能识别 numerical risk；
2. **方法贡献**：面向不同实现结构的解析数值适应度；
3. **机制证据**：提议器 × 适应度的 2×2 因果消融；
4. **外部证据**：从公式、结构和定点化一直验证到系统质量与真实 PPA。

“零采样方差”“放宽门槛会扩大可行集”“廉价筛选”均不再作为主张。

## 3. M0 — 最近工作与主张审计

### 3.1 必做阅读

对下列工作读取 method、evaluator、实验协议和实现，而非只读 abstract：

- LLM-RTL：COEVO、Verilog-Evolve、EvolVE、REvolution、EvoVerilog；
- 数值分析与精度搜索：LPQ、Daisy、FPTaylor、Real2Float；
- 强传统基线：FloPoCo、SPIRAL，以及 R2/R3/R4 所代表的精度约束 HLS / 近似硬件协同优化。

每项必须登记：

| 字段 | 要回答的内容 |
|---|---|
| 输入语义 | 自然语言、数学公式、计算图还是已有 RTL？ |
| 候选自由度 | 位宽、舍入、算法结构、微架构、自由 RTL？ |
| 观测统计量 | all-pass、pass fraction、容差 verdict、连续误差？ |
| 选择策略 | 门槛、退火、Pareto、标量化？ |
| 数值保证 | 采样估计、确定性枚举、解析计算、最坏界？ |
| 硬件口径 | 代理量、综合、STA、P&R？ |
| 统计协议 | seed、独立运行数、held-out、防数据泄漏？ |

### 3.2 Claim ledger

建立逐条主张台账，每条只允许三种状态：`verified`、`qualified`、`withdrawn`。至少覆盖：

- Boolean verdict 聚合是否丢弃误差幅值；
- 现有 LLM-RTL 是否使用 numerical risk；
- 现有精度工具是否同时做 RTL 结构搜索；
- COEVO 单测试用例的 pass 语义；
- Verilog-Evolve 的 GEMM evaluator；
- LPQ 的候选结构、评价量和输出层级；
- “比现有工作更深/更全”的每个比较维度。

### 3.3 M0 决策门

- 若已有工作完成“解析 numerical risk + RTL 结构搜索 + LLM 提议”，问题命题降为已知动机，
  贡献必须落在结构感知模型、系统级组合或交互效应证据；
- 若只有局部重合，加入强基线，不使用“首次”表述；
- 所有尚未核实的比较性陈述不得进入摘要、标题和贡献列表。

## 4. M1 — 命题与实验协议冻结

### 4.1 问题命题

冻结一般单阈值形式：

```text
v_h(x) = 1[|h(x) - f(x)| <= tau]
R(h)   = E[|h(x) - f(x)|^2]
```

正式材料包括：

1. 可测、平方可积条件下的 non-identifiability proposition；
2. `delta` / `B` 风险区间；
3. 相同 verdict bitmap、不同非零幅值的构造反例；
4. Boolean 输出、单位代价错误等反面边界；
5. strict all-pass 与 fractional pass-rate 的明确区分。

该命题定位为问题形式化，不声称是新的数学结果。

### 4.2 唯一指标协议

任何新实验启动前，先冻结以下字段：

- 参考函数、输入域与输入分布；
- 输出定点格式和黄金输出量化规则；
- verdict 阈值 `tau` 及聚合方式；
- numerical risk 的定义、单位、参考功率和频带；
- 暖机、对齐、测量区间与窗口；
- 场景版本、seed、held-out 划分；
- 饱和、溢出、非法候选的处理；
- 面积、时序、吞吐和功耗口径；
- ties、并列最优和 Pareto 保留规则；
- 解析计算、全枚举、固定格点和采样估计的层级标签。

### 4.3 候选与“结构”定义

预先定义 architecture class，避免把位宽变化写成结构生成：

- 结构类：LUT、插值、CORDIC、多项式、direct / polyphase 等；
- 数值配置：位宽、相位截断、舍入、饱和、截断位置；
- 微架构：展开、迭代、流水、资源共享；
- 纯模板参数选择与结构 IR / RTL 生成分开报告。

### 4.4 统计单位与最小效应

- 独立运行是统计单位，候选个体不是独立样本；
- pilot 只用于估计方差和运行成本，不用于最终显著性结论；
- 正式实验前冻结 seed 数、预算、主终点和最小有意义效应；
- 主终点优先选择 held-out hypervolume 或质量约束下的最小 PPA；
- 同时报 effect size、置信区间、失败率和负结果。

### 4.5 M1 决策门

协议必须能明确回答：同一候选在两种适应度下为什么得到不同反馈，以及终考为什么不会把训练
指标重新用作真值。协议签字前不修评价器、不跑正式搜索。

## 5. M2 — 评价基础可信化

### 5.1 修复范围

按唯一协议修复并审计现有 8 项评价器缺陷：

- 抽取折叠索引；
- SFDR 主瓣与已知杂散校准；
- 预测值与真值的同量对齐；
- `worst_drop` 标签；
- NCO 两字段 SQNR；
- Kendall tau-b 与并列集合；
- QPSK 功率；
- AWGN desired-signal SNR 基准。

修复只作为证据基础，不写成研究创新。旧产物保留，不覆盖；新产物使用新目录和新 manifest。

### 5.2 验证矩阵

| 层级 | 验证内容 | 验收条件 |
|---|---|---|
| 单元 | 单音、已知杂散、折叠 bin、功率与单位 | 解析期望与实现一致 |
| 模型 | 小位宽全空间、确定性格点、边界输入 | 误差来源与容差有书面解释 |
| RTL | 模型—RTL 逐位对拍 | 全空间或声明覆盖域内零失配 |
| 系统 | Parseval、对齐、带内/全带一致性 | 同一量之间比较，不混分母 |
| 综合 | 固定脚本、工具版本、SDC、FCW、接口 | 可复现且波动已校准 |

### 5.3 M2 决策门

- 若修复后旧现象消失，删除旧结论，不追求复现旧数字；
- 若模型与 RTL 存在未解释缝隙，该族不得进入正式实验；
- 若 Yosys/ABC 重复运行为确定性，工程阈值按 die/PPA 意义设定，不虚构统计波动。

## 6. M3 — 解析数值适应度有效性

### 6.1 最小任务组

至少覆盖三种不同模型形态：

1. **cmul**：整数域精确误差矩，小位宽全枚举；
2. **cordic_sincos / NCO**：全角度枚举与结构类变化；
3. **atan2 或 FIR**：确定性积分/格点或严格最坏界，并明确其非全域保证。

系统级 DDC 不承担局部模型正确性的首次验证，只用于后续外部证据。

### 6.2 必要对照

每族比较：

- strict all-pass；
- fractional pass-rate；
- 固定预算采样 SQNR/MSE；
- 解析 numerical risk；
- 全枚举或高可信统一重评真值。

报告：同分档 quality spread、tie rate、Kendall tau-b、选择损失、解析—真值偏差和计算成本。
不要求每个候选池都出现 pass-rate collision；单调池作为诚实边界保留。

### 6.3 适用边界

逐族列明：

- cross term 是否可解析；
- residual / 饱和是否存在并如何检测；
- 候选结构变化是否破坏模型假设；
- 输出是精确计算、最坏界、固定格点还是采样估计；
- 计算成本相对 RTL 仿真和综合是否有实际意义。

### 6.4 M3 决策门

- 至少两个不同结构族的解析适应度必须与统一真值排序一致到预注册标准；
- 只给边际矩、无法处理主导 cross/residual 的模型不得泛化为系统级解析适应度；
- 若解析适应度没有比强采样基线带来排序或成本优势，主张收窄为特定族的精确评价方法。

## 7. M4 — 2×2 机制实验

### 7.1 四格设计

| | Boolean test satisfaction | 解析 numerical risk |
|---|---|---|
| LLM 提议器 | A | B |
| 强非 LLM 提议器 | C | D |

主交互量预先统一符号后定义为：

```text
(B - D) - (A - C)
```

它回答：数值质量反馈是否使 LLM 相对强非 LLM 提议器获得更大收益。

### 7.2 公平性约束

四格保持一致：

- 候选表示和合法动作；
- 初始种群；
- 评价次数与停止规则；
- 档案、保留和迁移策略；
- 综合缓存；
- held-out 终考；
- 任务、场景和硬件后端。

同时报告 LLM token、费用、墙钟时间和无效候选率。强非 LLM 对手使用同空间的结构 mutation /
进化搜索，不使用弱 uniform random 充当唯一基线。

### 7.3 Pilot 与正式实验

1. 在可枚举空间做 pilot，确认实现无偏、预算足以观察差异；
2. 用 pilot 估算运行方差并冻结正式 seed 数；
3. 清空 pilot 对正式阈值的影响后运行多种子确认实验；
4. 所有格子用统一 held-out numerical quality + PPA 重评。

主报告项：

- held-out Pareto hypervolume；
- architecture-class coverage；
- unique non-dominated structures；
- evaluations-to-first-feasible；
- 质量约束下最小面积/时延/功耗；
- interaction effect 与置信区间。

### 7.4 M4 决策门

- 正交互且跨任务稳定：LLM × numerical fitness 进入主贡献；
- 数值适应度有收益但交互为零：保留解析适应度，LLM 降为可替换搜索器；
- 只有 LLM 主效应：论文转为结构提议研究，不能归因于解析适应度；
- 四格均无差异：报告负结果，重新审查候选空间是否过小或质量统计量是否仍不识别结构。

## 8. M5 — 结构生成与结构选择分轨

### 8.1 Selection track

在冻结参数化空间内比较算法类选择。能支持的结论仅为：

> formula-conditioned architecture selection

不能写成“LLM 从数学公式生成新硬件结构”。

### 8.2 Generation track

允许 LLM 生成或修改结构 IR、参数化模板或 RTL，但必须：

- 保持统一接口与数值契约；
- 独立做语法、握手、bit-true 和质量验证；
- 记录人工修复、失败尝试和结构去重；
- 把新增结构的验证成本计入搜索成本；
- 在未见公式或参数上复核，不只在训练任务上展示。

### 8.3 M5 决策门

- 若新增有效 architecture class 且统一重评后进入前沿，可使用“结构生成”表述；
- 若只重组模板参数或新增结构均无效，全文统一使用 architecture selection；
- 论文标题是否包含 LLM，由本阶段与 M4 的共同结果决定。

## 9. M6 — 系统级与硬件验证

### 9.1 系统场景

DDC 子链只在 M2 完成后启用。冻结并版本化：

- FCW、场景网格和相位比特覆盖；
- desired signal、blocker、AWGN 与 SNR 基准；
- 带内误差、EVM、BER 验证口径；
- 暖机、抽取相位、滤波状态和测量窗口；
- 训练场景与 held-out 场景。

旧 v1/v2 数字仅作审计历史，不作为新主张证据。

### 9.2 系统问题

本阶段回答三个问题：

1. 局部解析 numerical risk 能否组合成可信的系统质量判断？
2. numerical-fitness 搜索得到的结构是否在系统质量约束下保持优势？
3. 这些设计在真实综合 PPA 上是否形成新的非支配点？

筛选定理和 `eta` 不作为默认实验。只有闭式界同时通过 tightness 与 cost audit 才恢复。

### 9.3 硬件口径

- Yosys + Nangate45 必须带冻结时序约束；
- ice40 作为第二综合口径，不代替 ASIC 时序；
- 报告完整链综合，不能只相加模块面积；
- 吞吐按统一服务率换算，包含抽取、反压和流水；
- 有 Linux 资源后，对最终少量前沿点做 OpenROAD P&R；
- 没有 P&R 时明确称综合面积，不称物理面积。

### 9.4 强基线

- COEVO 式 Boolean satisfaction + Pareto 搜索，在匹配 DSP 任务上重建；
- 强采样 numerical fitness；
- 强非 LLM 进化/离散搜索；
- FloPoCo / SPIRAL / HLS 或可复现专业生成器产生的结构参考；
- 人工调优配置和小空间全枚举参考。

### 9.5 M6 决策门

- 若数值反馈只改变局部分数、不改变系统级选择或 PPA，降级为评价方法论文；
- 若收益来自不一致接口、格式、吞吐或时序，主张判失败；
- 若只在单场景成立，收窄适用范围并用独立场景复核；
- 只有超过预注册工程阈值的 PPA 差异才能称实际收益。

## 10. M7 — 论文与复现冻结

### 10.1 会议稿证据顺序

1. Boolean satisfaction 为什么不识别 numerical risk；
2. 解析数值适应度如何对不同结构给出可计算反馈；
3. 解析模型与 RTL / 统一真值的一致性；
4. 2×2 机制实验；
5. 系统级质量与真实 PPA；
6. 适用边界、负结果和失败族。

### 10.2 数据与复现

每次正式运行必须落盘：

- `manifest.json`：代码版本、任务、场景、seed、工具版本、预算；
- `results.json`：原始候选与指标，不只保存汇总；
- 解析模型层级与保证类型；
- 综合/STA/P&R 脚本和日志摘要；
- 图表生成脚本；
- 人工干预、重试与失败记录。

论文中的每个数字引用具体文件与字段。旧产物不覆盖，诊断数字不进入主结果。

### 10.3 最终投稿门槛

只有同时满足以下条件才进入投稿冻结：

- 最近工作与强基线完成逐条正文核实；
- 至少两个结构族的解析适应度经过独立真值验证；
- 2×2 正式实验完成多种子和统一终考；
- 系统级收益不依赖错误评价器或不一致口径；
- PPA 结果包含冻结时序约束；
- 负结果、失效边界和样本量限制写入正文；
- 所有数字可从仓库产物复现。
