# 第一章 绪论

## 1.1 研究背景与意义

### 1.1.1 通信芯片设计面临的生产率危机

无线通信系统的物理层是数字信号处理（DSP）算子密度最高的应用领域之一。从 5G NR 标准中的
CRC 校验、QAM 软解调、匹配滤波、数控振荡器（NCO）到快速傅里叶变换，每一个算子最终都要
以定点 RTL（Verilog/SystemVerilog）的形式实现在 ASIC 或 FPGA 上。这一"数学公式到
RTL"的转化过程至今仍以人工为主：工程师根据公式选择实现算法（如初等函数选用 CORDIC
迭代还是查表插值），决定定点化策略（字长、舍入模式、截断位置），再手工展开为流水线
化的寄存器传输级代码，最后通过仿真与综合反复验证。

这一转化之所以昂贵，根源在于它本质上是**在三个相互耦合的自由度空间中做联合决策**：

1. **算法结构空间**：同一数学函数存在大量数值上"近似等价"的实现结构。以正弦发生器为
   例，CORDIC 迭代、均匀查表加最近邻、查表加线性/二次插值、分段多项式逼近等结构在精度、
   面积、吞吐之间给出完全不同的折中曲线；
2. **定点化空间**：字长、舍入模式（就近舍入/截断/收敛舍入）、截断位置的选择决定了量化
   噪声的功率与谱形；
3. **微结构空间**：流水线深度、操作共享、乘法器结构（如 Karatsuba 分解）在不改变数值
   语义的前提下改变面积与时序。

工程实践中的常见做法是将三个空间**串行解耦**：先选算法结构，再做定点化字长优化，最后做
逻辑级优化。本文在后续章节将证明，这种"两级翻译"的串行解耦存在结构性损失——算法结构
选择时无法预见的精度-面积组合，只有在联合搜索中才会浮现。而人工流程受限于工程师带宽，
通常只能探索三个空间中极小的子集。

与此同时，通信物理层的精度需求天然是**可谈判的**：系统指标（如误码率、EVM）允许单个
算子的精度在足够高的水平上有所让步，以换取面积、功耗或时序的显著收益。这一点与通用的
"功能正确性"二值语义有本质区别——然而现有自动化设计工具与学术基准几乎都以"通过/不通过
测试"的二值口径评估 RTL 的正确性，无法表达"精度可谈判"这一通信领域的核心设计自由度。

### 1.1.2 大语言模型带来的机遇与"最后一公里"问题

2023 年以来，大语言模型（LLM）在代码生成上的能力跃迁使得"自然语言→代码"成为现实，
并迅速被引入硬件设计领域。从 VeriGen、RTLCoder 等微调模型，到 AutoChip、Chip-Chat、
VerilogCoder 等智能体系统，再到 2025 年 DeepMind 的 AlphaEvolve 将进化搜索与 LLM 结合
用于代码优化，"LLM 参与硬件设计"已经从概念验证走向工程实践。开源社区也在 2025 下半年
至 2026 年出现了将 AlphaEvolve 范式应用于 RTL 的第一批工作（EvolVE、REvolution、
COEVO 等）。

然而，把这条技术路线用于本文的目标——从数学公式生成通信 DSP 硬件——存在三个"最后一
公里"问题：

1. **基准缺位**：现有 RTL 生成基准（VerilogEval、RTLLM、CVDP）的输入几乎全部是自然
   语言描述，评估口径是二值功能正确性；没有一个公开基准以数学公式为输入、以连续数值
   精度为一等搜索维度、面向通信 DSP 算子族。评测基础设施的缺位使得"公式→RTL"方向上的
   方法进步无法被度量与比较；
2. **验证口径错配**：LLM 生成的 RTL 若仅以有限测试向量的仿真通过性作为适应度，评估
   本身是**随机变量**（激励随机、覆盖不全），进化过程实质上是在追逐一个带噪声的目标；
   而通信算子的数值正确性本可以由其数学规范**解析地或确定性地**刻画；
3. **搜索空间缺乏数学结构**：让 LLM 直接在原始 Verilog 文本空间中自由生成，等于放弃了
   数值语义层面全部已知结构（算术恒等式、舍入误差的线性可组合性、结构变换的精度不变
   性）。搜索效率因此受限——本文实验显示，原始文本空间的进化会被"算法类"的误差地板
   锁死，突破地板需要结构级跳变，而这类跳变在纯文本变异下极难发生。

### 1.1.3 研究意义

针对上述问题，本文的核心主张是：**把"验证"从有限采样升级为确定性证书，把"算法选择"
从离散目录查表升级为在证书携带的参数化实现空间中的导航，从而使 LLM 的搜索建立在数学
保证之上，而不是建立在采样的侥幸之上。**具体而言：

- **方法论意义**：提出评估 oracle 的三级层级（精确/穷举层、确定性积分层、声明性最坏
  界层），证明在这一层级上组织适应度，可以将 LLM 进化从"采样赌博"改造为"带证明的
  导航"，并以模分解引理等解析结果给出某些任务族上**零采样、零积分误差**的精确总体
  适应度；
- **工程意义**：构建了覆盖 7 个通信 DSP 算子族、110 个参数化实例的公开基准
  CommDSP-Bench，其评估流水线（iverilog/Verilator 仿真、Yosys ice40 与 Nangate45
  双口径综合）全部基于开源工具，为"公式→RTL"方向提供了可复现的度量基础；
- **实证意义**：以真实的 LLM 后端（DeepSeek deepseek-flash）在同一进化框架、同一预算
  下系统对比"采样适应度"与"证书适应度"两种范式，用可复现的实验数据回答"证书化适应度
  是否以及何时优于采样适应度"。

## 1.2 国内外研究现状

本文的工作处在三条研究线的交汇处：LLM 的 RTL 生成、进化式代码生成、以及数值软件中的
精度分析。本节分三条线综述（详细的逐篇对比见第二章），并指出交汇处的空白。

### 1.2.1 LLM 驱动的 RTL 生成

**需要训练模型的技术路线**以 RTLCoder（ICCAD 2024）、CodeV（2024）、CraftRTL
（ICLR 2025）为代表，通过指令微调或专用数据合成获得领域模型；2025 年起 RL 后训练
（CodeV-R1、VeriReason 等）进一步提高了功能正确率。这条路线的天花板是训练成本与数据
可得性，且模型对"数值精度-面积折中"这类连续目标没有原生的表达能力。**推理时/免训练
路线**以 AutoChip（2023）的仿真反馈修复循环为起点，经 VerilogCoder（ASP-DAC 2025）
的多智能体规划、NVIDIA ACE-RTL（2026）的上下文进化，发展出成熟的 agentic 流水线。
随着能力提升，经典基准的区分度迅速耗尽：VerilogEval 已被刷至 98% 以上，Synopsys 于
2025 年发布的 CVDP 基准（783 题）显示即便如此，真实工业任务上 SOTA 模型的 pass@1
仍不足 35%。

**进化式 LLM 代码生成**一线，AlphaEvolve（DeepMind，2025）确立了"LLM 作为变异算子 +
进化数据库 + 自动评估器"的范式，其开源复现 OpenEvolve 以 MAP-Elites 质量多样性网格
加岛屿模型成为事实上的标准框架。应用于 RTL 的第一批工作集中出现在 2025 年末至 2026
年初：EvolVE 比较了不同进化策略、REvolution 引入双种群与算子选择的 bandit 机制、
COEVO 以 NSGA-II 组织多目标（面积/时延/功耗）优化。这些工作共同确认了"LLM+进化"
在 RTL 上的可行性，但它们的评估口径仍然沿袭二值正确性加标量 PPA，输入仍以自然语言
为主，没有触及数学规范层。

**基准建设**方面，除上述功能口径基准外，TuRTLe（MLCAD 2025）开始纳入可综合性评估，
ResBench 关注资源效率，但"以数学公式为输入、以连续精度为可谈判目标"的基准在公开文献
中仍是空白。与本文最接近的前 LLM 时代先例是 CMU 的 SPIRAL——它把线性变换写成公式
并在公式空间中搜索最优实现，但只覆盖线性变换族，且不面向 LLM 时代的基础设施。

### 1.2.2 数值精度分析与定点化

从浮点/实数规范到定点实现的误差分析有深厚的积累：经典仿真驱动字长优化（Sung & Kum,
1995）、精度保证的静态分析（MiniBit，TCAD 2006）、基于仿射算术的区间传播、以及
FPTaylor/Daisy 等证书化误差界工具。算术算子生成器 FloPoCo 与多项式逼近环境 Sollya
代表了"应用专属算术"的成熟工程实践。然而这些工具都在**实现结构已经确定之后**才开始
工作——字长优化问题在文献中始终被形式化为"给定数据流图，分配字长"，而非与结构选择
联合。Herbie（PLDI 2015）证明了"以精度为目标的程序重写搜索"在浮点软件上的价值，其
e-graph 化的重实现（egglog 上的 Herbie）显示了等价饱和与误差分析结合的方向，但该线
工作不出硬件、不处理定点语义。

值得注意的是，上述积累中"证书"（对全体输入成立的误差界及其机器可检验的证明）的概念
从未进入 LLM 时代的生成系统——现有的 LLM RTL 工作全部以仿真通过性为验证手段。将证书
作为搜索空间的组织原则与适应度的计算方式，是本文试图填补的空白。

### 1.2.3 研究空白小结

综合三条线，截至 2026 年 9 月：

1. **公式级输入的基准空白**：没有公开基准以数学公式为任务规范、自动生成 golden 与
   激励、以连续精度（SQNR/SFDR）为可谈判搜索维度；
2. **证书化适应度空白**：没有工作将"对全体输入成立的误差证书"作为进化适应度的计算
   方式，也没有工作系统研究采样适应度的噪声与重尾病态对 LLM 进化的影响；
3. **质量多样性 × 数值精度空白**：现有 LLM-RTL 进化工作要么二值正确性、要么标量 PPA；
   以"精度-面积-吞吐"三维质量多样性网格组织搜索、使一次运行输出整条 Pareto 前沿的
   工作尚属空白；
4. **算法结构层的导航机制空白**：CORDIC 与查表插值这类"算法类跳变"在文本空间变异下
   极难发生（本文第五章的实验将给出定量证据），而将结构选择编码为证书携带的参数空间
   并让 LLM 在其中导航的系统方法尚未被提出。

## 1.3 论文主要研究内容

围绕"数学公式到 Verilog 的可靠自动生成"这一目标，本文完成三方面工作，构成递进的
三个创新点：

**创新点一：公式驱动的通信 DSP 硬件基准 CommDSP-Bench（第三章）。**
提出"锁定外部行为、放开内部实现"的基准设计原则，以 3GPP 物理层算子为任务源构建
7 个算子族、110 个参数化实例（复数乘法、正余弦发生、FIR、复数辐角、LLR 软解调、NCO、
匹配滤波、CRC），每个任务由纯数学规范驱动，自动生成 float64 golden 与防背题的新鲜
激励，以流式握手协议实现流水线无关的精度-面积-吞吐三 维可比性。对任务集进行了系统
审计：修复了导致 37% 实例基线失效的三类生成器缺陷，识别并如实报告了重尾误差分布
指标的方法学风险，并以 106 实例全量回归验证基准的自洽性。

**创新点二：证书化评估体系（第四章）。**
定义"公式-RTL 的 ε-等价"问题，提出评估 oracle 的三级层级：L1 采样层（现行做法）、
L2 确定性层（固定种子低差异格点上的整数域精确仿真、以及小输入空间上的全枚举）、
L3 声明性层（区间算术闭式最坏界）。证明模分解引理：整数域数据通路的输出量化误差
只依赖输入对 2^s 的残差，残差分布可由 2-adic 赋值混合精确求出，从而锚点任务（复数
乘法）的总体均值 SQNR 可**精确**计算（圆卷积形式），实现零采样、零积分误差的适应度。
给出四个算子族的证书模型并完成模型-RTL 逐位对拍验证（误差 < 0.1 dB）；发现并刻画
了重尾误差分布指标（LLR 族）下适应度估计的病态性。

**创新点三：证书携带的进化搜索范式与系统实验（第五章）。**
提出让 LLM 在"证书携带的参数化模板空间"中进化而非在原始文本空间中自由生成：每个
候选是模板的一点，其适应度由证书引擎确定性给出，面积由真实综合获得，结构选择
（CORDIC vs 插值 vs 表深）成为搜索的一等自由度。以 DeepSeek deepseek-flash 为
LLM 后端，在四个任务上与采样适应度基线（OpenEvolve 原生评估器）做同预算对比，
最终前沿统一重判；并完成 BER 证书目标、机制消融（空间/适应度因子分解）与
实现空间扫描等实验。实验表明：证书携带空间中的进化使结构跳变（算法类突破）
成为可系统性触达的事件——正余弦任务上第 5 次迭代即跨越采样基线 40 次迭代未能
突破的算法类地板（+20.4 dB），并在锚点任务上找到采样基线完全错过的精度可谈判
区域（前沿超体积 +54%）；机制消融确认这一优势的主导因子是搜索空间的显式结构，
证书的贡献在于确定性、代价结构与安全界。实验同时给出诚实的适用边界：重尾指标
（LLR 族）上均值证书不适应，综合预算导航中证书不预测成本（负结果）——
两者共同界定了方法的适用范围。

## 1.4 论文组织结构

本文共六章。第一章绪论。第二章综述相关理论与技术基础，包括 LLM 代码生成与 OpenEvolve
框架、定点算术的误差分析工具、等价饱和结构，并形式化定义本文的核心对象——ε-等价与
评估 oracle 层级。第三章介绍 CommDSP-Bench 基准的设计、实现、审计与全量回归验证。
第四章建立证书化评估体系，给出模分解引理及其证明、四族证书模型与三层验证链。第五章
以系统实验评估证书携带的进化搜索范式，包括与采样适应度基线的同预算对比、等价图导航、
误差预算分析与方法消融。第六章总结全文并展望后续工作。
