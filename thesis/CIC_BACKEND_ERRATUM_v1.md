# CIC bit-true 后端勘误 v1

- 日期：2026-10-08
- 状态：已确认；必须修复后完整重跑
- 影响范围：`formal-cic-witness-v1-20261008` 全部结果

## 发现方式

第一次正式执行完成了 414 条 main、276 条 held-out 和 138 条 stress 评价，但满宽 wrap 基线的
链级误差达到约 80–150，远高于冻结的 `q_budget=2.32929922807541e-5`。同时其输出出现间歇性的
`-1/+1` 饱和值，而三路无限精度参考的幅度低于 0.4。这一数量级冲突触发评价器审计；该轮数字不得
用于研究结论。

## 根因

`CICBitTrue.push()` 的最后一级梳状器使用扩展精度计算差值，却直接把这个 Python 整数送入固定
Q1.15 输出饱和。wrap 型 CIC 的前级状态都表示同一物理模数 `2^(B_max+1)` 下的值；最后一次差分
可能仍带一个整模数偏移。这个偏移本应在解释 `[B_(2N), B_max]` 位窗口时消去，却被错误地当成
真实幅度送去 sat16，造成稀疏的满幅脉冲。

这不是候选的新操作，也不改变冻结的候选空间。它是冻结语义“锁存 j 保存
`[B_j,B_max]` 位窗口”和“wrap 在梳状器中自愈”的实现缺口。sat 型候选没有模自愈性质，仍保留
扩展差值并由固定输出接口处理。

## 修复与验证

wrap 型候选在最后一级梳状器差分后、输出格式转换前，先取
`wrap_signed(current, W_full-B_(2N))`，得到冻结位窗口的有符号代表；随后继续执行原冻结的
`d=B_fmt-B_(2N)` 三段式转换与 sat16。其余运算、候选、场景、阈值和判据不变。

新增长序列回归：四个 `(R,N)` 组合各使用 13,312 个接近满量程的 signed 12-bit 输入，要求发生
内部 wrap，并要求满宽 wrap 输出逐样本等于等价 FIR。修复前该测试失败，修复后四组合全部通过。
正式场景的满宽基线抽查由约 80–150 降至 `0–4.2e-9`，且 `output_sat=0`。

## 重跑纪律

旧 run 目录和原始 `results.json` 原样保留，另加无效声明；不得修改或引用其中的排序与反转计数。
新运行必须使用新的 execution-v3、local-metrics-v3 和 run-id，重新执行 main、锁定主判定后再读取
held-out，最后执行 stress。不得与旧轮拼接。
