# CommDSP-Bench 任务族 V2 设计稿（待审）

- 状态：**设计稿，未实现**——供审阅；确认后按优先级逐任务实现
- 目标：基准集从 4 任务扩至 10 任务，构成 **3GPP-lite 物理层收发链全集**
- 任务源：3GPP TS 38.211（5G NR）/ TS 36.211（LTE）物理层标准条目的数学规范（非数据集——见调研结论）

## 0. 调研结论（为什么不用 SDR/5G 数据集）

| 生态 | 性质 | 不适用原因 |
|---|---|---|
| srsRAN / OpenAirInterface | 完整 5G/LTE C++ 协议栈 | 整机级非 kernel 级；golden 依赖数百万行软件栈 |
| RadioML / RF 记录 | IQ 采样数据集 | ML 分类输入，非硬件任务规范 |
| GNU Radio / RFNoC | SDR/FPGA 框架 | 实现载体；RFNoC（arXiv 2605.07704）做 PHY offloading 但未定义 kernel benchmark |

**结论**：kernel 级通信硬件 benchmark 是空白；正确路径 = 以 3GPP 标准的数学规范为任务源（SPEC P1 原则：锁定外部行为、放开内部实现），golden 自动生成。论文可写"任务族覆盖 3GPP 物理层原语"。

## 2. 新任务详细设计

### 2.1 `pss_corr` ⭐ 复数滑动相关器（定时同步内核）

**标准出处**：TS 38.211 §7.4.2.2（PSS：127 长 m 序列，x⁷+x⁴+1）
**任务定义（进 prompt）**：给定已知 127 点实值 ±1 序列 S（任务给定），对输入复数流 r[n] 做滑动互相关，输出每个 n 的相关值 c[n] = Σₖ S[k]·r[n−k]（127 项复数乘累加）。
**IO（stream_v1）**：
- 输入：`i_in`, `q_in` 各 16 位 signed Q1.15（复数基带样本）
- 输出：`c_re`, `c_im` 各 24 位 signed（Q9.15，127×Q1.15 累加界）
**激励**：BPSK 调制的 m 序列段 + QPSK 数据段拼接 + AWGN（SNR=10 dB，评估器注入，DUT 与 golden 见同一含噪输入——公平性由"同输入对同 golden"保证）；`distribution: pss_bpsk_noisy`
**Golden**：`numpy.correlate(noisy_input, S)` 逐位浮点
**指标**：SQNR（相关输出 vs golden；多字段取最差）
**初始程序（朴素基线）**：127 级移位寄存器 + 每拍 127 次实数乘累加（纯 FIR 结构，直接型满展开）
**算法空间（仅论文分析，不进 prompt）**：直接型/转置型 FIR 结构复用；序列 ±1 特性 → **乘法器退化为加减**（进化应自主发现——相当于 fir 的系数特化）；匹配滤波器折叠；并行度-面积权衡
**防作弊**：流式无限输入空间天然免疫；相关长度固定 127（锁定）
**评估代价**：同 fir（综合可能较重：127 tap 展开的基线综合时间长，需验证；基线可先写位串行版本控制代价）

### 2.2 `phase_est` ⭐ 复数辐角提取（CFO/信道相位估计内核）

**标准出处**：CP 相关频偏估计（TS 38.211 §5.3.1 OFDM CP 结构）与锁相环共用的相位检测内核
**任务定义**：输入复数 (I, Q)，输出 atan2(Q, I) 的定点角度。**角度编码与 cordic_sincos 完全一致**（θ·2¹⁵/π，[-π, π)）——两个任务共享编码，论文叙事：CORDIC 族解是同一硬件的两种模式。
**IO**：
- 输入：`i_in`, `q_in` 各 16 位 signed Q1.15
- 输出：`theta` 16 位 signed 线性角度码
**激励**：均匀幅角复数（幅值 0.2–1.0 均匀，避免纯原点）；`distribution: uniform_complex`
**Golden**：`np.arctan2(q, i) * 32768 / π`，clamp [-32768, 32767]
**指标**：SQNR
**初始程序**：16 象限折叠 + 256 点 |Q/I| 查表（粗）
**算法空间**：CORDIC 向量模式（迭代级数 8–16）/ 八分象限折叠+查表+插值 / Q/I 比值+多项式 arctan / CORDIC 与 sincos 复用（硬件共享发现的潜在机会）
**防作弊**：输入为连续复平面点集，无限空间
**评估代价**：同 cordic_sincos（轻）

### 2.3 `qam_llr` ⭐ 64QAM 软解调（LLR 计算）

**标准出处**：TS 38.211 §5.1.3（64QAM Gray 映射，表 5.1.3-1）
**任务定义**：输入均衡后的星座点 (I, Q)（Q4.12，值域 ±8）与固定噪声方差（任务卡锁定 σ²），输出 6 个比特的 LLR。**Golden 用精确 log-sum-exp**，DUT 允许 max-log 等近似——近似算法与精确算法的取舍是本任务的核心权衡。
**IO**：
- 输入：`i_in`, `q_in` 各 16 位 signed Q4.12
- 输出：`llr0..llr5` 各 16 位 signed（Q8.8，理论界 |LLR|≲σ⁻¹·max_dist×256）
**激励**：随机 6 bit → Gray 映射到星座 + AWGN（SNR=20 dB，σ² 任务卡锁定）；`distribution: qam64_awgn`
**Golden**：浮点精确 LLR：L_b = ln(Σ_{s∈S_b=1} e^{−|y−s|²/2σ²}) − ln(Σ_{s∈S_b=0} …)，按 38.211 Gray 映射分桶
**指标**：SQNR（6 个 LLR 逐字段取最差）
**初始程序**：max-log 逐比特（每 bit 两半星座各 8 点 min 距离）——工程标准做法作为基线
**算法空间**：max-log / max-log+查表 / 分段线性近似（每 bit 3–5 段）/ 混合；**这是通信芯片教科书级的精度-面积折中任务**
**防作弊**：星座点+噪声的连续输入空间
**评估代价**：中（多输出字段，仿真同量级）

### 2.4 `crc24a` 流式 CRC24A（3GPP 必选校验）

**标准出处**：TS 38.212 §5.1.1（CRC24A，g(D)=D²⁴+D²³+D¹⁸+D¹⁷+D¹⁴+D¹¹+D¹⁰+D⁷+D⁶+D⁵+D⁴+D³+D+1，即 0x864CFB）
**任务定义**：流式 CRC——每输入一个 16 位数据字，输出到当前字为止的 24 位累积 CRC（MSB-first，非反射，初值 0，符合 3GPP）。
**IO**：
- 输入：`data` 16 位
- 输出：`crc` 24 位
**激励**：均匀随机 16 位字流；`distribution: uniform_words`
**Golden**：Python 位精确流式 CRC（与标准逐位一致，全 2¹⁶ 前缀可验证——**穷举可验**）
**指标**：**`exact_match`（新注册 metric 类型）**——CRC 不允许近似；正确率 < 100% → 哨兵。这是论文的诚实对照：**不是所有通信任务都该精度可谈判**，框架两者都支持（该任务 MAP-Elites 维度退化为 area×吞吐，注册制的直接用例）
**初始程序**：逐位 LFSR（16 步/字，多周期）
**算法空间**：位串行 LFSR / 字节查表（256×24 ROM）/ 双步展开 / 16 位并行反馈矩阵（一步一字）/ 流水——经典硬件 CRC 优化问题，面积-吞吐前沿丰富
**防作弊**：2¹⁶ 前缀上穷举验证 golden；流式无限数据空间
**评估代价**：轻（纯逻辑，无数值仿真负担）

### 2.5 `scrambler` Gold 序列加扰（3GPP §7.3.1.1）

**标准出处**：TS 38.211 §7.3.1.1：c(n) = x₁(n+1600) ⊕ x₂(n+1600)，双 31 位 LFSR（x³¹+x³+1），x₂ init = c_init
**任务定义**：任务卡锁定 c_init；每输入一个 16 位数据字，输出该字与 Gold 序列对应 16 位的 XOR。
**IO**：
- 输入：`data` 16 位
- 输出：`scr` 16 位
**激励**：均匀随机数据字；`distribution: uniform_words`
**Golden**：Python 双 LFSR 步进 1600 + 序列生成（位精确，**可穷举验证前缀**）
**指标**：`exact_match`（同 crc24a 理由）
**初始程序**：双 31 位 LFSR 逐位生成 + 16 位拼装（多周期）
**算法空间**：逐位 / **N 步并行展开（预计算跳步矩阵——线性 GF(2) 结构，可一次算 16/32/64 位）** / 序列 ROM；吞吐-面积权衡经典
**防作弊**：流式 + 序列周期 2³¹−1，无限空间
**评估代价**：轻

### 2.6 `fir_decim` 抽取滤波器（接收链降采样）

**任务定义**：2:1 抽取的低通 FIR（32 抽头，截止 0.25·fs_in，任务给连续系数）——每两输入样本输出一个（**stream_v1 的速率转换用例**：输入侧背靠背消费 2 样本/输出）。
**IO**：
- 输入：`x` 16 位 signed Q1.15
- 输出：`y` 40 位 signed Q9.30（全精度，同 fir）
**激励**：高斯白噪声；`distribution: gaussian_white`
**Golden**：浮点卷积（连续系数）×2³⁰ 刻度，仅取偶数位置输出
**指标**：SQNR
**初始程序**：直接型全抽头
**算法空间**：多相分解（天然二相）/**半带特性利用（近对称零系数）**/CIC 替代/位串行——fir 的结构变体任务，链路叙事（接收链抽取）
**评估代价**：同 fir
**注**：速率转换对 stream_v1 是首例——testbench 需验证 in 侧 2 样本/1 输出的握手语义（每 2 个输入握手拍对应 1 个输出拍，与延迟无关的吞吐语义已由协议保证，实现时需在 tb 生成器中处理"输入计数=2×输出计数"的对齐）

## 3. 新增注册表条目（对 SPEC §10 的影响）

| 注册点 | 新条目 |
|---|---|
| metric 类型 | `exact_match`（crc24a/scrambler：逐字精确，哨兵=任何失配） |
| 激励分布 | `pss_bpsk_noisy`, `uniform_complex`, `qam64_awgn`, `uniform_words` |
| Golden 分发 | `pss_corr`（序列相关）, `phase_est`（arctan2）, `qam_llr`（精确 LLR）, `crc24a`/`scrambler`（位精确）, `fir_decim`（系数卷积） |

`exact_match` 任务的 combined_score：正确 → 0.6·(面积项)+0.4·(吞吐项)（无精度项）；失配 → 哨兵。MAP-Elites 维度建议 `(area, throughput)` 二维（precision 维对 exact 任务无信息量）。

## 4. 实现优先级与工作量

| 序 | 任务 | 工作量 | 理由 |
|---|---|---|---|
| 1 | `phase_est` | 小 | 最轻、与 cordic 编码复用、立即闭环 |
| 2 | `qam_llr` | 中 | 精度可谈判性最经典 |
| 3 | `crc24a` | 小 | exact_match 注册 + 链路叙事 |
| 4 | `scrambler` | 小 | 同上 |
| 5 | `pss_corr` | 中 | 相关器 + 噪声激励注入 |
| 6 | `fir_decim` | 中 | 速率转换首例，tb 需改 |

每任务交付物：task.yaml + initial_program.v + golden/stimulus 注册 + 闭环验证（基线指标 vs Python 预测一致）+ SPEC 更新。

## 5. 对论文叙事的升级

- 基准定位句从"四个 DSP 内核"→ **"3GPP-lite 物理层收发链 kernel 全集（10 任务，3 个二值精确 + 7 个精度可谈判）"**
- 新增实验素材：qam_llr 的 max-log vs 精确 LUT 前沿（通信教科书权衡的进化复现）；crc24a 的纯 PPA 前沿（与竞品 AT 口径同性质任务上我们的框架照样工作）；phase_est 与 cordic_sincos 的编码共享（算法族复用叙事）
- 诚实边界句：框架主张精度可谈判，但不强制——exact 任务由注册制支持，两者共存于同一链路（CRC 必须精确，LLR 可以近似）——这比"全部近似"的立场更强

## 6. 风险与开放问题（请审阅时决断）

1. **pss_corr 基线综合代价**：127 tap 直接展开的基线可能综合超时——基线先写 8 tap 位串行版？还是任务定义降为 63 长？（倾向：序列长 63，与 5G PSS 127 的偏差在任务卡中注明"缩短以控评估代价"）
2. **qpsk_mod 是否纳入**：算法空间过小（映射表），建议**不纳入**，用 fir_decim 替代链路位（当前提案已如此）；若需要"最简锚点"叙事可后补
3. **qam_llr 的 SNR 选择**：20 dB 单点 vs 多 SNR（多 SNR 使激励分段更真实但分析复杂；V1 建议单点，参数已任务卡化可扩展）
4. **噪声注入位置**：pss_corr/qam_llr 的 AWGN 由评估器注入（golden 与 DUT 同输入）。备选：噪声预烧进激励文件（等价）。倾向评估器注入（fresh seed 复用现有机制）
