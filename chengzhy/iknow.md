# VeriEvolve：面向通信 DSP 链的精度可谈判 RTL 设计空间探索

> 本文是文章与系统建设的共同主线。§1 说明问题，§2 解释系统与已有进展，§3–§7 给出当前规划、主张与实验的对应关系。新增研究实验先写明它回答本文的哪个问题；探索结果经验证后再进入文章结论。当前规划更新于 2026-10-08，尚待验证的内容均按研究问题处理。

## 1 背景

### 1.1 通信物理层是一条相互耦合的数值处理链

无线通信硬件并不是若干独立算子的简单集合。从基带比特到射频波形，再从接收样本恢复出比特，数据会依次经过编码、调制、变换、滤波、采样率转换、同步、均衡和判决。每个阶段都可能改变误差的幅度、频谱、相关性和时间位置，因此一个模块的实现选择只有放回具体链路后，才能判断它是否满足系统需求。

下面给出本文采用的通信物理层算子地图。它表示研究对象之间的关系，不表示当前仓库已经实现完整收发机。

```text
发射端

比特 ──▶ 扰码/前向纠错(FEC) ──▶ 星座映射 ──▶ 成形 FIR ──▶ 插值/DUC ──▶ DAC/RF
                                                        │
                                                  NCO + 复数混频
                                                        │
信道 ════════════════════════════════════════════════════╪════════════
                                                        │
接收端                                                  ▼

ADC ──▶ AGC ──▶ NCO/DDS ──▶ 复数混频 ──▶ FIR ──▶ 抽取 ──▶ 同步 ──▶ FFT
                 └──────────── 当前 DDC 主实验链 ────────────┘          │
                                                                        ▼
                               信道估计/均衡 ──▶ 软解调/对数似然比(LLR) ──▶ FEC 译码

旁路状态与控制：频偏估计、载波/定时环、增益控制和饱和恢复会反向影响上述数据通路。
```

这张图可以进一步抽象为五类算子与状态：

1. 波形生成与多速率前端，包括 NCO/DDS、复数混频、FIR、插值、抽取、CIC、分数重采样和 PFB；
2. 变换与线性代数，包括 FFT/IFFT、信道估计、矩阵分解和均衡；
3. 同步与跟踪，包括相关、频偏估计、定时恢复和载波环；
4. 检测与译码，包括星座判决、LLR、解扰和 FEC；
5. 非线性控制与补偿，包括 AGC、削峰和数字预失真。

同一个数学算子还对应多种硬件实现。例如正余弦可以使用 LUT、插值、CORDIC 或分段多项式，复乘可以使用直接型或三乘法分解，FIR 可以使用直接型、转置型或多相结构。每一种实现又要决定字长、舍入、饱和、流水和资源共享。因而，通信硬件设计不是单一的“选位宽”问题，而是四类决策的组合：

```text
数学分解 × 近似实现结构 × 定点策略 × RTL 微结构
                       │
                       ▼
              链级质量 × 面积 × 时序 × 吞吐
```

本文的长期目标，是把通信公式、流式接口和链级质量要求编译为一个可验证的定点 RTL 设计空间，并在其中寻找质量与硬件代价的 Pareto 前沿。现阶段仓库已经建立 7 个算子族、110 个参数化实例的基准基础；决定性实验首先聚焦 NCO、复数混频、FIR 和抽取组成的数字下变频（DDC）子链，而不是把尚未实现的任务表述为完整收发机。

### 1.2 为什么单算子最优不等于链级最优

传统算子设计通常在模块边界上报告 SQNR、SFDR、最大误差或均方误差。这些指标适合验证一个实现，却未必足以替整条链选择实现。原因不是单算子研究本身不合理，而是局部指标会压缩掉下游仍然关心的信息。

设某个算子的量化误差为 `e`，其后的混频、滤波和抽取组成变换 `T`。系统最终观察到的不是 `e`，而是 `T(e)` 以及它与其他误差源的交叉项。两个局部总误差功率相近的候选，可能具有完全不同的频谱和相关结构：一个候选的误差会被后级滤波器抑制，另一个候选的误差则可能在抽取时折叠进通带。饱和、状态递推和闭环控制还会进一步破坏简单的逐模块排序。

因此，局部算子指标仍然适合构建实现库、校准数值模型和排除明显不合格设计；但最终的候选保留、淘汰和硬件取舍，应由部署链中的逐位一致（bit-true）行为与系统级契约决定。本文首先研究的不是“链级评价一定优于局部评价”，而是更具体的问题：

> 在算法结构可变、存在滤波与采样率变化的通信链中，局部候选排序在什么条件下能够保持，什么条件下会改变；若会改变，可靠筛选至少需要保留哪些误差信息？

### 1.3 现有方法分别解决了问题的一部分

相邻领域已经提供了成熟工具，但它们通常固定了本文希望联合处理的某些自由度。

| 方法路线 | 已经擅长的部分 | 留下的问题 |
|---|---|---|
| 专业算子生成器与 IP | 为 CORDIC、正余弦、FIR、FFT 等产生高质量参数化实现 | 精度要求多停留在算子接口，缺少下游滤波、抽取和系统质量的统一语义 |
| 字长优化与精度约束 HLS | 在给定数据流图上联合选择字长、调度、绑定或近似算子 | 计算图或实现集合通常预先给定，难以同时改变数学分解、近似结构与多速率链 |
| SPIRAL、数值重写与等价饱和 | 系统地探索公式分解、求值顺序或精确等价 RTL | 重点是语义等价或运行代价，通常不把可谈判的定点误差和链级通信质量作为一等目标 |
| LLM 生成与进化式 RTL | 能从自然语言或反馈中提出跨文件、跨结构的代码修改 | 常以二值功能正确性为门槛，在自由文本中搜索；缺少共享的定点语义、链级连续质量和可公平比较的动作空间 |

在目前核对的文献范围内，尚未发现一个工作流同时完成以下闭环：以数学公式和流式状态语义为输入，在同一表示中搜索严格等价分解、近似实现与定点 RTL，并用包含采样率变化的端到端数值契约和真实综合结果选择候选。这个组合，而不是其中任意单项，是本文要验证的研究空缺。

### 1.4 为什么还要引入 LLM

如果设计空间只是一个规模很小的候选表，穷举、整数规划或普通启发式搜索通常已经足够。LLM 的研究价值不能来自“能够从几个模板中选一个”，也不能来自绕过公共规则生成无法比较的自由文本。本文先用带类型中间表示（typed IR）定义合法的数学分解、近似原语、定点操作与连接规则，再用确定性的逐位一致评价和真实综合判断候选。LLM 只承担候选提议，不承担正确性判断。

LLM 的潜在价值来自设计空间的组合性。面对新的公式、链路位置和质量约束，它可以同时读取数学恒等式、硬件原语、历史候选和失败诊断，并提出多步、跨层的结构动作。例如，它可以把一个旋转识别为“粗粒度查表加残差旋转”的组合机会，而不是只在固定 LUT 上继续调整位宽。支持库决定哪些构件合法，LLM 若有额外价值，则应体现在有限评估预算下如何组合和使用这些构件。

由此得到本文最具风险、也最具辨识力的假设：

> 在共享同一带类型中间表示、原语、动作集合、初始条件、评价器和失败计费的前提下，利用公式与链级契约语义的 LLM 提议器，能否比枚举、遗传编程（GP）、束搜索或蒙特卡洛树搜索（MCTS）等语法驱动方法更快找到新的质量—面积折中，并迁移到未见公式或未见约束？

这个假设必须由同语言、同预算实验决定。可支持它的证据包括随评价次数变化的前沿质量、首次找到可行设计的成本、有效提案率、跨任务迁移和公共语法内的新组合；单个偶然优胜设计不足以构成结论。若同预算优势不成立，论文应保留 typed IR、链级评价与搜索结果，而不把 LLM 写成已证实的贡献。

### 1.5 研究问题与实验版图

本文按依赖关系组织四组实验，避免在基础前提尚未成立时直接归因于 LLM。

| 研究问题 | 实验对象 | 主要对照 | 回答什么 |
|---|---|---|---|
| RQ1：局部排序何时改变？ | DDC 中的 NCO、复乘、FIR 与抽取 | 局部 SQNR/SFDR、候选精确线性传播、经典频谱模型 | 链级评价是否提供局部指标与强解析基线之外的信息 |
| RQ2：联合设计是否必要？ | 共享带类型中间表示上的结构与定点动作 | 联合搜索、先固定结构再调字长、先成本后质量、固定结构字长优化 | 联合搜索能否稳定找到分阶段流程遗漏的质量—面积点 |
| RQ3：LLM 是否改善搜索？ | 与非 LLM 方法完全共享的动作程序 | 枚举、遗传编程、束搜索、蒙特卡洛树搜索、LLM | LLM 是否提高样本效率，而不是扩大自己的搜索空间 |
| RQ4：收益能否迁移？ | 未见公式、链路位置与部署约束 | 静态实现库、检索和跨任务搜索基线 | 提议策略是否具有超出单任务调参的泛化能力 |

这四个问题分别检验评价、设计空间、提议策略和泛化。已有联合搜索实验未达到成功判据，该结论保留。后续方法开发围绕本文定义的系统继续进行；新的正式比较须说明与旧实验的关系，使用独立登记的协议和未参与开发的测试任务。LLM 的收益必须在相同设计空间与评价条件下单独检验。

## 2 我们最终想完成什么

我们希望做出一套从通信数学公式自动得到硬件实现的系统。

用户提供两类输入：

1. 数学公式，说明硬件要计算什么；
2. 使用要求，说明输入输出格式、采样率、允许多大误差，以及更关心面积、速度还是功耗。

系统最后给出可综合的 Verilog，并报告这个实现放进通信链路后的质量和硬件成本。这里的 Verilog 是描述数字电路的代码，综合工具可以把它转换成逻辑门组成的电路。

下面是我们希望最终实现的完整流程。当前已打通 typed IR 到硬件生成和评价，并完成真实 LLM 的开发试跑；开发用质量测量已经能驱动多轮提案，面积、时序和正式场景反馈尚未接入循环。

```text
数学公式 + 使用要求
          │
          ▼
LLM 理解公式，提出一种实现方案
          │
          ▼
带类型中间表示（typed IR）
          │
          ├── 规则检查：连接、位宽、采样率和状态是否合法
          │
          ▼
确定性硬件生成器
          │
          ├────────▶ 数值模型 ──▶ 放进整条通信链评价质量
          │
          └────────▶ Verilog ───▶ 仿真和综合，得到面积与速度
                                      │
                                      ▼
                         把质量、成本和失败原因反馈给 LLM
                                      │
                                      └────▶ 提出下一种方案
```

这个过程会重复多轮。系统不只寻找一个答案，而是保留多种有意义的取舍。例如，一个实现面积更小但误差稍大，另一个实现面积更大但质量更高，它们都可能是有效结果。

### 2.1 typed IR 是什么

typed IR 的中文是“带类型中间表示”。它位于数学公式和 Verilog 之间，可以理解为一张格式严格、机器能够检查的电路设计表。

“中间表示”表示它既不是最初的数学公式，也不是最后的硬件代码。“带类型”表示表中的每个部件都写清楚自己能接收什么、会输出什么。系统至少会记录：

- 当前使用的是实数还是复数；
- 数值是否有符号，占多少位；
- 前后部件的采样率是否一致；
- 在哪里舍入、截断或饱和；
- 哪些部件带有内部状态；
- 各个部件怎样连接。

这些信息相当于插头的形状。两个部件的接口不匹配，系统会在生成 Verilog 之前拒绝这个方案，避免把明显错误的电路送去仿真和综合。

以正余弦公式为例，当前 typed IR 支持直接查表、CORDIC，以及粗查表加残差 CORDIC。CORDIC 通过多次移位和加减逐步逼近旋转结果。分段多项式属于后续可扩展结构。表深、迭代次数和部分定点参数已经可以修改；流水、迭代复用和更多内部位宽选择还需要扩展表示与后端。

我们不让 LLM 直接任意编写 Verilog，主要原因是自由文本很难保证连接、位宽和定点规则一致，也难以确认不同搜索方法是否使用了相同的设计空间。typed IR 把可修改的部分明确列出来，使 LLM 的探索能力能够被约束、验证和复现。

#### typed IR 是我们自己创造的吗

不是全部由我们创造。

用中间表示连接高级描述与底层代码，是编译器领域的通用方法。带类型的中间表示同样是成熟思想。例如，MLIR 允许不同领域定义自己的操作和类型，再把高层数据流逐步转换成目标代码；CIRCT 在这一基础上定义了面向硬件模块、端口和数据类型的表示。这些通用思想不是 VeriEvolve 的发明。

参考资料：

- [MLIR Language Reference](https://mlir.llvm.org/docs/LangRef/)
- [CIRCT HW Dialect](https://circt.llvm.org/docs/Dialects/HW/)

我们自行设计的是面向当前通信实验的 `verievolve-search-ir-v1`。它不是通用编译器，也不是 MLIR 或 CIRCT 的替代品，而是一套规模较小、可以直接用于实验的领域专用表示。它目前只覆盖数字下变频链所需的结构和参数。

自研部分主要包括：

1. 面向数字下变频链的节点种类，包括相位累加器、正余弦实现、复数乘法、滤波和二倍抽取；
2. 面向定点硬件的类型信息，包括有无符号、总位数、小数位数、舍入和饱和；
3. 面向多速率链路的采样率类型，使滤波前后的速率变化可以被检查；
4. 把数学上等价的分解与近似硬件实现分开记录，避免把近似算法误当作严格等价变换；
5. 从同一份表示分别生成数值模型和 Verilog；
6. 供 LLM、遗传编程和其他搜索方法共同使用的修改动作；
7. 稳定的设计编号和版本字段，使每个实验结果能够对应回唯一的公式、契约和候选结构。

这些内容是我们的工程设计。它们是否能成为论文贡献，还要看实验是否证明这套表示能够支持可靠的公式到硬件搜索，并带来已有方法没有得到的结果。不能仅仅因为代码由我们编写，就把 typed IR 本身称为研究创新。

#### 当前的 typed IR 具体长什么样

当前表示采用 JSON 结构。下面是一份经过简化、但保留真实字段名称的数字下变频候选：

```json
{
  "schema_version": "verievolve-search-ir-v1",
  "formula_version": "ddc-formula-v1",
  "contract_version": "CONTRACT_DDC_v1",
  "kind": "ddc",
  "adc_input": {
    "format": "complex Q1.11",
    "rate": "1/1"
  },
  "phase_accumulator": {
    "kind": "phase_accumulator",
    "width": 32
  },
  "nco": {
    "kind": "phasor_compose",
    "split_bits": 8,
    "coarse": {
      "kind": "lut_sincos",
      "depth": 128,
      "interpolation": "nearest",
      "phase_bits": 10
    },
    "residual": {
      "kind": "cordic_sincos",
      "stages": 7,
      "phase_bits": 16
    },
    "product_rounding": "nearest_ties_to_pos_inf",
    "product_saturation": "sat"
  },
  "mixer": {
    "kind": "complex_multiply",
    "rounding": "nearest_ties_to_pos_inf",
    "saturation": "sat"
  },
  "filter_decimator": {
    "kind": "polyphase_fir_decimator",
    "coefficient_bits": 16,
    "product_drop": 0,
    "accumulator_bits": 0,
    "rounding": "nearest_ties_to_pos_inf",
    "saturation": "sat",
    "input_rate": "1/1",
    "output_rate": "1/2"
  }
}
```

这份候选表达的硬件方案是：使用 32 位相位累加器，把角度分成粗略部分和剩余部分；粗略部分使用 128 项查表，剩余部分使用 7 级 CORDIC；两部分相乘后采用指定舍入和饱和规则；滤波与二倍抽取使用多相结构。

其中，`nearest_ties_to_pos_inf` 表示就近且半值向正无穷舍入，`sat` 表示数值超出可表示范围时固定到最大值或最小值。`product_drop: 0` 表示乘法结果不主动丢弃低位。`accumulator_bits: 0` 是当前 schema 约定的“使用完整累加宽度”，并不是使用零位累加器。

上面的 `Q1.11` 表示一个 12 位有符号定点数，其中 11 位用于小数部分。真实文件不会把它写成一个字符串，而会完整展开：

```json
{
  "kind": "fixed",
  "signed": true,
  "width": 12,
  "frac": 11
}
```

采样流也有自己的类型。例如，抽取后的输出速率是输入速率的一半：

```json
{
  "kind": "stream",
  "value": {
    "kind": "complex",
    "component": {
      "kind": "fixed",
      "signed": true,
      "width": 16,
      "frac": 15
    }
  },
  "rate": {
    "num": 1,
    "den": 2
  }
}
```

因此，typed IR 记录的不只是“选择查表还是 CORDIC”，还记录了数据怎样流动、每一级使用什么数值格式，以及采样率在哪里发生变化。

#### LLM 实际输出什么

系统已有两种提案接口：局部动作接口修改已有候选，完整方案接口从 Formula Request 生成 Architecture Plan。真实 LLM 开发试跑使用后者。下面是局部动作接口的例子：

```json
[
  {
    "kind": "wrap_compose",
    "path": "/nco"
  },
  {
    "kind": "change_interpolation",
    "path": "/nco/coarse/interpolation",
    "value": "quad"
  }
]
```

第一步表示把原来的正余弦节点拆成粗略角度与剩余角度的组合。第二步表示把粗略部分的查表方式改为二次插值。`path` 指明修改位置，类似文件系统中的路径。

当前允许的结构动作包括：

- 在查表和 CORDIC 之间切换；
- 改变查表插值方式；
- 加入或移除粗略角度与剩余角度的组合；
- 在直接型滤波和多相滤波之间切换；
- 修改位宽、表深、CORDIC 级数、舍入方式等数值参数。

动作执行后，系统会重新检查整份候选。不存在的路径、越界的位宽、非法的采样率连接和未知字段都会被拒绝。LLM 不能修改公式版本和部署契约，也不能通过输出任意子树扩大自己的搜索空间。

#### 为什么要自己设计这一版 IR

我们没有直接让 LLM 写 Verilog，主要有五个原因。

1. **保证合法性。** 类型和采样率在生成硬件前就能检查，减少低级连接错误。
2. **保证公平。** LLM 和传统搜索只能使用相同节点、参数和修改动作，实验比较的才是提议能力，而不是谁拥有更大的设计空间。
3. **保证可复现。** JSON 可以直接保存到实验记录中，同一候选会得到稳定的设计编号。
4. **保证模型与硬件一致。** 同一份 IR 同时生成数值模型和 Verilog，避免评价模型与实际硬件描述不同步。
5. **允许组合新结构。** 候选不是一个模板编号。粗略查表与剩余 CORDIC 可以由已有节点组合产生，不需要为每个组合手写一个新的候选名称。

当前选择 JSON，而不是直接建立完整的 MLIR 或 CIRCT 方言，是为了先用较小的实现成本验证研究问题。若以后扩展到 FFT、同步、均衡或更复杂的控制状态，这套 JSON 表示可能需要升级为更通用的图结构，或者映射到 MLIR/CIRCT。当前版本的目标是把实验做严谨，不是宣称已经完成了通用的通信硬件编译器。

#### 距离“任意公式到硬件”还缺什么

当前 Formula Request 会把公式显式传给 LLM，但检查器仍只接受预先定义的 DDC 计算图：相位累加、正余弦生成、复数混频、滤波和二倍抽取。LLM 能改变各部分的实现结构和参数。支持新的数学计算图还需要扩展公式入口与转换规则。

以当前公式为例，用户想表达的是：输入信号先乘以一个旋转相位，把目标频段搬到低频；随后滤波；最后每两个样点保留一个。系统把这个公式展开成下面的结构：

```text
输入样点
   │
   ├──────────────┐
   │              ▼
   │       相位累加器 → 正余弦实现
   │              │
   ▼              ▼
        复数混频
            │
            ▼
          FIR 滤波
            │
            ▼
         二倍抽取
            │
            ▼
          输出样点
```

要达到真正通用的“数学公式到硬件”，还需要补齐四层能力：

1. **公式入口。** 把用户提供的公式、输入输出和使用要求转换成高层计算图。目前只有预先编写的数字下变频公式。
2. **硬件知识库。** 为每类数学运算准备多种可验证的实现方法，并写明它们的适用范围。例如正余弦可以使用查表、CORDIC 或多项式。
3. **通用转换规则。** 把高层公式逐步变成 typed IR，再由确定性后端生成数值模型和 Verilog。每条转换规则都需要验证，不能只依赖 LLM 的文字判断。
4. **LLM 设计循环。** 让 LLM 根据公式、使用要求和上一轮结果选择转换规则与硬件结构，再用真实评价结果指导下一轮修改。

因此，我们准备使用 LLM 驱动整个设计过程，但不会让 LLM 独自承担全部工作。LLM 负责理解、规划和提出修改；知识库提供可用部件；typed IR 保存可检查的方案；确定性后端负责生成硬件；仿真、链级评价和综合负责给出真实结果。

当前已有显式但固定的 DDC 公式入口、第 2、3 层的受限实现，以及真实 LLM 的方案生成与语法修复。下一步需要连接评价反馈、支持微结构选择，并逐步让已有算子能够组成新的公式图。正式搜索收益仍待验证。

### 2.2 LLM 在流程中负责什么

LLM 负责理解问题并提出下一种设计方案。每一轮，它可以读取数学公式、使用要求、可用的硬件部件、上一轮的质量与面积，以及失败原因。它随后给出一组明确的修改动作，例如：

- 把查表实现换成 CORDIC；
- 把一个角度拆成粗略部分和剩余部分，分别采用不同实现；
- 调整某一段数据的位宽；
- 改变舍入位置；
- 在合法位置更换滤波或抽取结构。

LLM 不负责宣布自己的方案正确，也不负责决定自己的方案更好。规则检查器负责判断设计是否合法；数值模型和 Verilog 仿真负责检查行为；综合工具负责测量硬件成本；整条通信链的评价结果负责判断这个设计是否值得保留。

因此，真正完成“数学公式到硬件”的不是一个单独的 LLM，而是 LLM 与确定性工具组成的闭环。LLM 像设计人员，负责提出有方向的修改；typed IR 像统一图纸；生成器像自动化工厂；仿真、链级评价和综合工具负责验收。

### 2.3 我们已经完成到哪里

我们已经在数字下变频链上完成了大部分基础设施。数字下变频用于把接收机中的目标频段搬到较低频率，当前实验链由正余弦发生、复数混频、滤波和抽取组成。

目前已经完成：

1. 用 typed IR 表示多种正余弦和滤波结构；
2. 从同一份 typed IR 生成数值模型和 Verilog；数值模型严格采用硬件中的位宽、舍入和饱和规则；
3. 检查数值模型与 Verilog 是否一致；
4. 把候选放进完整数字下变频链测量质量；
5. 用真实综合结果测量面积；
6. 建立公共修改动作，使传统搜索和未来的 LLM 能够修改同一个设计空间；
7. 完成传统搜索的正式比较。

正式比较一共计入 320 个候选方案，从 5 组不同的随机起点分别运行。联合搜索在其中 2 组运行中找到了面积明显更小的设计，但另外 3 组没有稳定复现，因此当前结果不能证明联合搜索可靠地优于分阶段设计。按照事先确定的实验顺序，本轮没有继续接入 LLM。

这意味着我们已经搭好了从 typed IR 到硬件生成、验证和评价的主干，但还没有证明 LLM 能带来额外收益。当前不能把“LLM 更会设计硬件”写成实验结论。

### 2.4 如果继续研究 LLM，下一步做什么

接下来要把方法开发和论文实验分开。方法开发允许反复修改提示信息、硬件知识库、typed IR 和错误反馈；这时的运行只用于发现问题，不用于证明论文结论。等生成流程稳定后，再冻结任务、预算和比较方法，开展正式实验。这样既能保证最终证据可信，也不会让实验规则阻止我们开发真正想做的方法。

我们下一步要开发的流程是：

```text
数学公式、接口和使用要求
            │
            ▼
LLM 先规划计算步骤和硬件结构
            │
            ▼
把规划转换成可检查的 typed IR
            │
            ▼
确定性生成器产生数值模型和 Verilog
            │
            ▼
规则检查、仿真、链级质量评价和综合
            │
            ▼
把明确的失败原因和设计结果反馈给 LLM
            │
            └───────────进入下一轮修改
```

现有公共动作接口一次只允许很少的局部修改。它适合比较不同搜索方法，因为每种方法拥有完全相同的动作；但它也可能限制 LLM 发挥作用，因为 LLM 擅长先理解公式，再提出由多个步骤组成的结构方案。下一版原型不直接废弃这些动作，而是在它们上面增加一层规划：LLM 可以先提出完整方案，系统再把方案拆成一系列经过检查的动作。这样既保留可靠的生成后端，也能检验 LLM 是否真的会组合硬件知识。

为了改进这条流程，我们先观察四件具体事情：LLM 生成的方案有多少能够通过规则检查；第一次生成能否得到可运行硬件；收到错误原因后需要几轮才能修好；在相同生成次数下能否找到已有方法没有找到的结构。开发阶段用一组公开的小任务快速迭代。流程稳定后，再把从未参与开发的公式和使用要求作为最终测试，并与传统搜索使用相同的硬件部件、评价方法和生成次数。

正式比较从多组起点运行，并在未参与开发的任务上保持一致，才能说明 LLM 在数学公式到硬件的过程中具有额外价值。在此之前，我们只说已经实现了生成流程，不把调试现象写成实验结论。

### 2.5 CIC 第二条链现在走到哪里

CIC 实验不是为了挽救前面联合搜索得到的 S0，也不使用 LLM。它要回答一个更基础的问题：
“只看单个模块的局部量化误差，能不能可靠地选择整条通信链里的硬件实现？”DDC 已经给出一次反例，
CIC 用带递归状态、抽取和溢出语义的另一种结构检查这个机制能否迁移。

2026-10-04 已批准第一次冻结：候选怎样生成、每一级怎样截断、内部寄存器怎样 wrap 或 saturate、
以及最终怎样转换成固定 Q1.15 输出，都不能再根据后续结果修改。下一步只实现逐位一致的整数模型并合并
输出完全相同的候选，不计算最终链级质量。预检清单完成后还要第二次冻结，之后才允许正式跑数。

2026-10-08 已完成这一步。28 个纸面候选经过整数模型检查后得到 23 个不同实现。减少的 5 个不是
被实验淘汰，而是名字不同、实际计算完全相同的重复项。wrap 与 saturation 没有被合并：压力输入已经
证明它们会产生不同输出。预检清单还写死了场景、代码指纹和测试输入，但正式质量尚未计算。

现在停在第二次冻结门前。批准后，我们才会运行参考链和 23 个候选，比较局部预测与整条链的实际排序。

2026-10-08 已批准第二次冻结。接下来开始正式计算：先确认三种参考实现给出相同输出，再运行 23 个候选，
最后比较局部预测和整条链的排序。候选与场景从此不能根据结果调整。

三种参考实现已经对齐。正式计算前还要补一个定义：局部 SQNR 用什么固定功率作 dB 标尺，以及 N=3、
N=4 共用同一输入时由哪条参考链校准 30 dB 噪声。补充稿建议使用固定半功率标尺，并用 N=4 理想 CIC
校准每个 R 的公共输入。它只让公式唯一，不改变候选和判据；确认前不跑正式质量。

### 2.6 CIC 正式实验得到了什么

CIC 的正式实验已经完成。第一次运行暴露了一个实现错误：最后一级差分没有先把 wrap 状态还原为正确的
有符号位窗口，导致正常输出偶尔被误写成 `-1` 或 `+1`。那次运行完整保留，但只作为调试记录。修复后，
四种满宽 CIC 在 13,312 个接近满量程的输入上都与等价 FIR 逐点相同，然后才用新编号从头重跑正式实验。

正式结果支持一个很具体的结论：只看每一级丢了多少低位，不能判断整条 CIC 链的质量。wrap 和
saturation 使用相同位宽、相同舍入和相同裁剪，所以 Hogenauer 局部公式认为它们完全一样；但 CIC 的
递归状态会不断越界。wrap 保留模运算，后面的梳状器可以把回绕抵消；saturation 会把状态钉在最大值或
最小值，已经丢掉的信息无法恢复。因此四组 wrap/saturation 对照在整链结果中全部被明显分开，而且在
没有参与主判定的 held-out 场景中方向不变。

这说明 DDC 里发现的核心问题不是某一条链的偶然现象：局部误差大小不足以描述误差进入整条通信链后会
怎样传播。DDC 的原因是频移、滤波和抽取；CIC 的原因是递归状态、模回绕和饱和。我们的评价方法因此需要
知道链级结构和数值语义，而不能只把每个算子的一个 SQNR 数字相加。

这项结果不证明 LLM 更好，也不挽救之前联合搜索的 S0。它只完成评价轴的第二条链验证。LLM 的价值仍要
在单独的正式实验中检验：让 LLM 和传统搜索使用同一 typed IR、相同硬件部件、相同生成次数，并比较谁
更能提出有效的结构变化。

### 2.7 DeepSeek 开发试跑的真实结果

2026-10-08 已用 DeepSeek 官方 API 在公开 DDC 开发任务上试跑。它第一次就给出合法的完整方案：16 级
CORDIC 加 16 位直接对称 FIR；系统把它编译成 typed IR、整数模型和 Verilog。第一次错误试跑暴露了能力
清单表达不完整的问题：混合结构的 `coarse`/`residual` 被写成字符串，模型无法知道还需要哪些参数；修正
清单后才成功。这说明错误反馈和公开语法本身都属于方法的一部分。

该方案的独立验收结果分开记录：bit-true 与 iverilog 逐位对拍通过，开发用链级质量为
`Q_dev=4.2987039978778864e-09`，FIR mask 合法，测试中混频器和 FIR 均无饱和。标准 600 秒成本评价在
ABC 阶段超时；保持 RTL、Nangate45 Liberty 与综合脚本不变，将开发诊断上限延至 1200 秒后，映射在
904.3758489999454 秒完成，得到面积 `41425.51 μm²`、33012 个标准单元。因此 600 秒记录只表示面积
当时未知，不表示设计或 RTL 不可综合。完整产物在
`examples/comm_dsp_bench/experiments_system/formula_to_rtl_dev/dev-ddc-deepseek-20261008b/`。

这次运行还暴露了当前 typed IR 的微结构缺口：16 级 CORDIC 被生成器完整展开为无流水组合链，LLM
只能选择级数，不能选择组合展开、流水或迭代复用。若要让 LLM 优化 codegen，这些选择需要进入所有
proposer 共用的公开语法，而不能作为 LLM 私有能力。

这次运行仍只是方法开发，不是 LLM 与 GP/随机搜索的正式比较。它已经证明“真实 LLM 能提出受约束的
结构方案并进入可验证硬件后端”，但还没有证明 LLM 的搜索收益。

## 3 文章要回答什么

我们要建立一套面向通信 DSP 的硬件生成系统：输入数学公式、流式接口和使用要求，由 LLM 提出算法结构、定点策略与微结构，再通过可检查的表示生成 Verilog，用链级质量和真实硬件代价选择实现。

文章围绕一个问题展开：**在允许数值近似的通信任务中，怎样让 LLM 有效探索硬件结构，同时让每个候选的数值行为、时序行为和评价结果可以核查？**

这个问题对应三项工作：定义贯穿公式与硬件的数值和流式语义；把链级质量与硬件代价反馈给结构探索；通过独立验证和公平对照确定系统与 LLM 各自带来的收益。会议稿聚焦可完成的闭环，硕士论文展开模型、编译规则、工程验证与失效边界。

## 4 完整系统怎样工作

### 4.1 首个可交付版本

首个版本以 DDC 为端到端主线，把正余弦、复乘、FIR 和抽取作为可复用部件。CIC 的现有结果先承担状态与溢出语义验证；其 RTL 生成与搜索接入需要单独验收。后续支持由已验证部件组成的新公式图，逐步扩展到其他通信任务。仅改变 DDC 的参数或约束，结果就限定为参数或约束泛化；未见公式泛化需要新的计算图测试。

输入必须明确公式、数据格式、输入域、采样率、复位与状态更新规则、允许误差、目标工艺和时钟要求。自然语言可以辅助填写，进入生成器前要转换成可检查的结构化规格。缺少决定数学含义或接口行为的信息时，再与用户讨论。

输出是一个可复现的设计包：Verilog、规格与实现计划、独立参考结果、验证报告、综合面积、约束时序报告，以及质量与硬件代价的 Pareto 前沿。前沿保留互有优劣的实现，用户再根据部署要求选择。若预算内没有找到达标实现，系统报告已搜索范围与具体未满足项；时序或综合超时记为未知。

首个版本的完成条件是：从规格入口到设计包能用统一命令运行；已登记的验收任务通过数值、握手和硬件检查；中断能恢复，结果能重放。功耗与布局布线作为后续能力，只有对应测量完成后才写入硬件收益结论。

### 4.2 贯穿公式和硬件的表示

为了让结构、精度与流水都能变化，我们把设计信息分成相互关联的三层。初期沿用现有 Python 和 JSON，先完成语义与接口，再根据扩展成本决定是否引入 MLIR/CIRCT。

| 层次 | 记录什么 | 必须检查什么 |
|---|---|---|
| 公式图 | 数学运算、连接、采样率、延迟状态、初始条件、系数来源 | 单位与类型一致；循环必须经过明确状态；计算含义唯一 |
| 定点实现图 | 运算结构、各边位宽与小数位、舍入与溢出位置 | 每个整数操作含义明确；精确重写满足条件；近似误差有评价途径 |
| 调度与资源计划 | 流水位置、迭代次数、资源共享、缓冲与握手 | 数据与相位对齐；无丢样和重复；吞吐与延迟可测；反压下状态正确 |

类型检查只能排除一部分错误。采用实数恒等式重排表达式后，有限字长中的中间溢出和舍入可能改变结果，因此每条变换都要标为严格等价或数值近似，并写明条件。

数值语义要明确区分算术右移、向零截断、半值向正无穷舍入、半值取偶数、模回绕和饱和。现行公共实现使用明确名称；旧字段仅由历史兼容入口映射，以保留旧实验的实际含义。

流式语义还要区分样点序号与时钟周期。当前 DDC 相位随成功接收输入而推进；新增流水或迭代实现必须保持同一规则。若部署端要求相位按物理时钟连续推进，需要另一个显式规格。对不能停顿的 ADC 输入，还须验证输入速率与缓冲能力，而不能仅靠 ready 信号隐藏处理速度不足。

### 4.3 LLM 的探索闭环

```text
数学公式和使用要求
          │
          ▼
结构化规格与独立数学参考
          │
          ▼
LLM 或传统方法提出结构、定点和调度方案 ◀──────────────┐
          │                                           │
          ▼                                           │
类型与变换条件检查 → 整数模型 → RTL 生成                │
          │                      │                    │
          ▼                      ▼                    │
链级质量评价              逐位、握手与状态验证           │
          └──────────┬───────────┘                    │
                     ▼                                │
               综合与静态时序分析                      │
                     │                                │
                     ▼                                │
           候选档案、Pareto 前沿与失败诊断 ──────────────┘
                     │
                     ▼
              独立终验与设计包
```

为了发挥 LLM 对公式与结构的理解，每次提案附一段简短设计理由：改变了什么，预计改善哪个量，可能牺牲什么，以及哪项测量能检验。理由不参与打分。反馈提供真实误差、饱和位置、最差场景、面积、关键路径、吞吐和失败类别；最终留出任务的详细结果只在档案冻结后查看。

搜索同时保留结构探索和局部细化。LLM 提出跨层组合，普通离散搜索负责廉价参数邻域；这种混合方案需要计入全部搜索成本，并与使用相同局部细化预算的传统方案比较。简单可靠的种群与多起点闭环先行，树搜索是否值得加入由公开开发任务决定。

LLM 扩展实现库是另一项工作：它可以查阅论文、提出新分解，甚至编写新原语的实现草案。新原语先验证类型、数值模型、RTL、参数边界与适用条件，再版本化加入公共库。正式的固定空间比较中，各提议器使用同一库；扩库实验则单独比较达到合格实现所需的时间、调用和人工修复成本。

### 4.4 验证怎样避免模型和代码一起出错

| 检查对象 | 参考与方法 | 能说明什么 |
|---|---|---|
| 数学功能和数值质量 | 从公式单独构造浮点或高精度参考，检查尺度、符号和样点映射 | 候选是否在规定场景中计算了正确的数学任务，并满足误差要求 |
| 整数实现 | 逐位模型与 RTL 对拍，覆盖负数、边界、半值、溢出和状态 | RTL 是否实现了声明的整数语义 |
| 原语与变换规则 | 可行时全域枚举或开源形式验证，记录前提和参数覆盖 | 被检查范围内的等价或性质成立 |
| 流式与状态 | 按 `valid && ready` 入队出队比较，插入停顿、反压、复位及长序列 | 数值序列、顺序、抽取相位和状态推进正确 |
| 进展与性能 | 下游最终接收等明确环境假设下检查完成性，测量延迟和吞吐 | 硬件不会通过一直不输出逃避比较 |

从同一 IR 生成模型与 RTL 有助于一致性，但两者可能共享错误。因此独立数学参考和小规模枚举必须保留。全域验证按原语和规则逐步建立；有限随机对拍只标记实际覆盖，不提升为全空间正确性。

误差结果分别标记为解析计算、全枚举、固定场景计算、采样估计或最坏界。固定种子和固定格点可以复现，但仍可能存在覆盖误差。解析公式也要登记输入分布、独立性、溢出假设和数值计算误差。

链级质量统一声明参考、分母、频带、前导、测量段和样点对齐。新任务默认同时报告原始误差和校准后误差；只有部署允许相应校准时才以校准后误差验收。既有冻结实验保留原口径。实现误差与通信总 EVM、BER 分开报告。

### 4.5 硬件代价与运行管理

微结构先补 CORDIC 的流水实现，再补迭代复用，然后处理 FIR 的加法树、流水及乘法器共享。每一步都联合检查数值行为、吞吐、延迟和面积。流水可能改善关键路径，也会增加寄存器；面积与综合时间的变化都需要实测。

面积继续来自真实综合。时序使用固定 Liberty、时钟与输入输出约束，配合 OpenSTA 分析映射网表；检查是否存在未约束路径，并明确寄生参数假设。ABC 的延迟目标只能作为映射设置，最终是否达标由静态时序报告判断。[OpenSTA 官方说明](https://openroad.readthedocs.io/en/latest/main/src/sta/README.html)

搜索保留质量、面积、吞吐和延迟维度；已知部署时钟或输入速率用于该部署点的可行性判定。任何新增硬门都要写清对应的外部要求或评估成本防护理由。综合超时的设计保留未知成本状态，重试策略对所有提议器一致。

统一运行记录绑定规格、候选、后端、场景和工具版本。缓存按这些身份分别存储；修改调度后，只有确认整数语义和样点序列保持时才复用数值结果，RTL 与时序仍重新验证。检查点恢复不能重复计费或覆盖已有结果。每次运行记录调用数、token、实际费用、评价次数、CPU 与墙钟时间，包括失败和重复提案。

工具任务在独立工作目录执行，设置进程、内存与时间限制，超时清理整个子进程组。新原语的可执行草案在隔离环境验收；公式和提案不能改写评价器、参考或实验结果。工具不可用、API 故障与候选错误分别记录，基础设施故障不作为算法或硬件劣势。

### 5.1 2026-10-08：阶段 B 第一批实现

本批把候选评价变成提议循环的公共接口。规则提议器和 LLM 提议器都能在计划合法后调用同一个评价器；质量不达标会带着实测值和失败类别进入下一轮，评价器异常则停止并标为 `inconclusive`，不会伪装成候选失败。开发命令默认启用固定公开单音的质量反馈，`--plan-only` 只用于检查计划与编译路径。

质量状态现在分为测量是否成功与数值是否低于请求上限。输出同时记录要求范围、证据范围、`evidence_role=development_only` 和 `deployment_acceptance=false`。因此开发单音可以筛选提案，但不能替代正式场景、`Q_main` 或部署验收。循环尚未包含综合面积和约束时序反馈。

RTL 验证改为按 `valid && ready` 接收事务并依次与整数模型比较，主动插入输入空隙和输出反压，并检查停顿期间 `valid` 与数据保持以及最大周期内的进展。当前组合实现通过；是否真正兼容不同延迟，只能在流水和迭代实现加入后由测试确认。

本批未修订数值评价公式，因而不登记 `AUDIT.md`，也没有新增论文实验数字。`search_ir` 测试共 820 项通过；全 `tests/` 尝试还受端口绑定、缺少 SOCKS 依赖和缺少外部 API key 等环境条件影响，不能表述为全仓回归通过。完整命令和结果见阶段 B 实施记录。

本节第一批结束时，舍入/溢出语义仍是下一项；其完成情况记录在 §5.2。之后把综合档案与预算接入公共循环，再进入 C 阶段的流水、迭代和约束时序。修复数值评价器时仍须同步登记 `AUDIT.md`，列出受影响结果并使用新产物目录。

### 5.2 2026-10-08：数值语义边界完成

现行计划、typed IR 构造器和提议器公开空间不再使用容易误读的 `rne/trunc`。新名称
`nearest_ties_to_pos_inf` 表示 `floor((v+2^(s-1))/2^s)`，`floor` 表示有符号算术右移；历史字段只在
兼容入口中映射到这两个含义。新候选会保存显式名称，已经落盘的候选和实验结果不修改。

独立参考没有复用模型中的“加半后右移”实现，而是用 Python 整数的商和余数判断舍入方向，并枚举正负
半值、符号解释、饱和和模回绕边界。它发现旧生成 RTL 在原位宽中加半值可能先回绕；修复为先符号扩展
一位。该失败和影响范围已登记到 `AUDIT.md` §8.17。旧网表及面积继续绑定旧源码；新实验必须使用新
run-id，不能把两版硬件代价混合。

历史证据与当前运行已经分流。旧 Stage C 面积仍可逐文件、逐摘要只读审计，旧 pilot 通过显式
`legacy_v1` 配置复现 72 个状态转移；该配置不进入当前公开搜索空间。当前面积缓存和校准入口会因候选或
RTL 身份变化拒绝旧结果，不能把旧网表的面积重标到修复后的 RTL。只读审计和可复用缓存因此是两个不同
接口。

这项工作完成了第四项 P0，但没有产生新的论文性能结论。阶段 B 剩余工作转为公共候选档案、缓存、恢复、
综合反馈和统一预算；之后才进入微结构与约束时序。

## 6 用文章约束实验

### 6.1 每次实验先回答一个问题

实验开始前，在对应文章主张下填写一张简短实验卡，并随 `manifest.json` 保存。必填内容如下：

- 对应的文章段落、C 编号，以及本次可被推翻的假设。
- 改变哪个因素，其他因素怎样固定；基线为何能检验这个假设。
- 主指标、统计单位、最小有意义差异、预算和停止条件。
- 开发、正式测试与留出任务的划分，以及已经看过哪些结果。
- 正、负、不确定三种结果分别怎样影响文章和下一步。
- 规格、代码、工具、场景、种子、输出路径与字段来源。

一个实验若说不清会改变文章哪句话，就先留在想法列表。工程回归绑定 C2 的正确性或可用性要求即可，不必写成研究假设。

开发过程中允许依据反馈改方法。正式比较开始前冻结方法、任务、预算和判据；评价器缺陷通过勘误、新版本和重跑处理。留出任务一旦被用于修改方法，就转为开发材料，后续泛化判断需新留出集。文章约束的是问题与证据标准，结论随证据更新。

### 6.2 最小实验矩阵

| 实验 | 对应主张 | 核心比较 | 主要输出与判定 |
|---|---|---|---|
| 工程验收 | C2 | 独立参考、整数模型、RTL；不同调度与停顿模式 | 数值、协议、状态、时序和重放报告。失败先修复，其他研究结果暂停引用 |
| 评价方法复核 | C1 | 局部指标、已验证的相干线性传播、完整整数链 | 误差、排序与选择后果，保留强基线有效的场景；优先整理已有产物 |
| 微结构开发实验 | C2、C3 | 固定算法与定点语义，比较组合、流水、迭代实现 | 面积、时序、吞吐、延迟及映射成本；先确认真实折中存在 |
| 固定空间搜索比较 | C3、C4 | 随机、离散进化或语法搜索、LLM；分阶段设计作为既有问题的对照 | 固定预算下的达标设计率、前沿质量、首次达标成本和失败类型 |
| 反馈消融 | C4 | 相同提议器分别获得局部质量与链级质量；必要时增加连续数值与阈值反馈对照 | 统一终评下的选择后果；将反馈作用与提议器作用分开 |
| 扩库探索 | C5 | 基础库、规则或检索扩展、LLM 辅助扩展 | 新增实现的有效性、开发与验证成本、未见配置表现 |

固定空间比较必须共享完整方案语法、动作集合、起点、评价后端、失败计费与缓存规则。除随机外，至少使用一个经过同等开发调优的强传统提议器；在可控子空间上用枚举检查搜索离参考前沿有多远。专业生成器用于核对硬件实现质量，移植与接口适配成本单独记录。

同时报告按提案次数、实际评价成本和墙钟时间计算的结果，避免一个方法用更多内部计算换取表面上的样本效率。Pareto 前沿覆盖度使用冻结的尺度和参考点；任务与独立运行作为统计单位，不能把同一次搜索产生的候选当成独立重复。种子数和费用上限在开发耗时标定后登记，正式结果不用于反推这些设置。

若 LLM 没有稳定收益，文章保留系统、传统搜索结果及边界。若只在某类结构或约束下有效，主张限定到该条件。旧联合搜索负结果继续作为独立实验报告。

## 7 待验证的想法

以下是方法候选，先做有停止条件的探索实验。正结果须在独立条件复验后进入文章的结果部分；负结果保留在对应记录中。

| 想法 | 为什么可能有用 | 最小验证 | 没有效果时怎样处理 |
|---|---|---|---|
| 结构提案后用传统搜索细化参数 | LLM 可能擅长组合，离散搜索适合局部调参 | 给不同结构提议器相同参数细化预算，比较 C4 的前沿和成本 | 保留最有效的传统方法，缩小 LLM 角色 |
| 根据失效环节反馈 | 位宽错误、链级杂散和时序失败需要不同修改 | 固定任务与总预算，比较标量反馈和带环节定位的反馈 | 使用更简单的反馈，不继续堆叠提示 |
| 按适用条件选用解析模型或整数链评价 | 已有 DDC 强线性基线说明部分场景可用更简单计算 | 对冻结候选比较模型误差、排序和真实耗时 | 若没有成本收益，保留完整整数评价；未经可靠界限支持的估计仅用于排序，不能硬淘汰候选 |
| 从论文中提出可验证的新组合 | 可补充人工模板库的覆盖 | 先写变换、条件和预期后果，再做原语验收与未见配置测试 | 将无收益结构留档，不纳入主要贡献 |

近期继续执行 B：质量门槛、按握手验证、开发测量反馈和数值语义边界已经接通；接下来补公共档案、缓存、恢复、综合反馈和统一预算。完成后再进入流水、迭代和约束时序，避免在运行身份与成本计费不稳定时提前跑正式搜索实验。

### 7.1 复数旋转小实验计划

状态：开发计划草案，尚未实现或运行。下面的位宽、误差门槛和预算是拟定设置，不是实验结果。

**问题。** 给出数学关系 `y = x * exp(-j*theta)` 和可用模块后，LLM 能否正确连接、调整实现，并从
“先算正余弦再复乘”换成“直接旋转输入”？本轮检查选型、组合与实现能力，作为 C2/C5 的开发检查。

**现有代码。** `design_gen.py::gen_cordic` 只输入角度，内部从固定向量开始，属于多周期正余弦生成器；
`chains/ddc/rtl_gen.py::_nco_map_cordic` 提供组合展开的正余弦运算；`certfit/tpl_cmul.py` 有三乘法和四乘法
复乘。已检查的这些路径还不能直接作为每拍接收任意复数输入的旋转模块。当前没有同一规格下的完整比较，
因此尚不能指定面积最小的实现。

**实施路径。** 先做独立 RTL 任务。复用现有数值语义、仿真调用、按握手收数的方法及 Nangate45 面积
交叉核对；为旋转任务单独提供端口、参考和测试。现有 Search IR 的公式、候选、端口与综合检查绑定整条
DDC，整条复用需要改动更多层；受限表达式方案还需新增解释和代码生成。这一轮先复用底层工具。

具体接入使用 `evaluator.py` 的任务注册、任意端口测试台及仿真/综合入口，新增旋转任务卡、激励、
独立数值参考和专家直接旋转实现。验收还需补三项：输出反压及停顿数据保持检查；无输入气泡时的连续
接收检查；每个输出分量的均方根误差和测试最大绝对误差。当前测试台 `out_ready` 恒为 1，输出在下降沿
收集，加入反压时应按上升沿实际握手统一记录事务。已有平均吞吐数值不能代替每拍接收检查。
Nangate45 入口已存在；复用时另核对映射完整性、面积来源和运行档案。

**规格草案。** 实部和虚部均为 16 位有符号数，数值等于整数码除以 32768；角度为 16 位无符号码，
65536 对应一整圈。输出每个分量使用 17 位有符号数，仍除以 32768，从而容纳全输入范围旋转后的幅度。
旋转总增益必须为 1；CORDIC 的增益补偿包括在被评价硬件内。输出按就近舍入，半值向正无穷；输出
范围外按饱和定义。内部位宽和舍入允许变化，所有影响计入最终误差。无反压时每拍接收一个输入；不同
延迟允许但必须登记。输出停顿期间数据保持，测试不得丢失或重复事务。

**评价。** 独立数值参考直接计算上述数学关系，不复用候选的 CORDIC 或查表算法。开发初始门槛暂定为
每个输出分量的均方根误差不超过 2 个输出最低位、测试集最大绝对误差不超过 8 个输出最低位。
这些是检查流程的开发门槛，没有通信系统部署含义。公开测试包含随机输入、零、小幅值、满幅、象限
边界及相邻角度码；另留一组独立输入，只在候选选择后测试，失败如实保留。通过采样测试不等于全输入
误差保证。门槛与输入清单在首次候选评价前冻结；修改后建立新版本，旧测试转为开发数据。

协议通过、误差达标的实现才进入面积比较。面积来自同一 Nangate45 综合流程，所有补偿、查表、寄存器
和握手逻辑均计入。当前流程没有可靠时序验收，本轮时序状态统一记为未完成；每拍接收的仿真结果不代表
达到某个实际工作频率，也不据面积宣布综合性能最优。

**对照和 LLM 范围。** 先准备专家实现：查表加四乘法复乘、查表加三乘法复乘、CORDIC 正余弦加复乘、
直接旋转流水 CORDIC，以及粗查表加残差旋转。最多选 8 个配置，配置与来源在评价前登记。专家实现
统一过独立参考与协议检查，至少两种计算方法通过后才调用 LLM；否则停止并修复检查流程。
LLM 可阅读同一批组件及实现，输出固定接口的 RTL，修改模块连接、内部位宽、舍入和流水位置。
本轮保持组件内部的算法步骤，新增算法留待下一轮。模型不得修改参考、测试、综合脚本或验收门槛。

**预算。** 专家配置最多 8 个；LLM 做两次独立尝试，每次最多 3 次提案，总计最多 6 次模型调用。
每次输入最多 8000 token、输出最多 4000 token，总上限 72000 token，失败和重试都计入。
最多 14 次真实综合，每次 600 秒；综合累计上限 8400 秒，自动运行总上限 4 小时，任一上限到达即停。
这些是资源上限，不是耗时预测或 API 费用授权；付费调用前仍需按实际模型价格确认费用。
重复提案占提案次数；缓存命中记录为评价请求，不计作真实综合。所有配置绑定当前源码和工具身份。

**如何决定下一步。** 能生成两种分解、正确处理事务并满足误差门槛，说明小任务具备继续探索的基础。
LLM 能交付合格实现，说明具备本轮限定的选型与组合能力；是否改善面积另与专家结果比较。若只能重现
专家实现，记录为重现；若失败，区分数值、连接、协议和工具问题。两个独立尝试只用于开发诊断，不作
搜索优势的统计结论。下一轮才决定是否开放组件内部改写，并加入同预算传统搜索和反馈对照。
