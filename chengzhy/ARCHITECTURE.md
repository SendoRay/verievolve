# VeriEvolve 架构说明

> 状态：2026-10-09 起草。这份文档只回答四个问题：LLM 的输入是什么、它输出什么、数学变换在哪里发生、系统的哪些部分是固定的。
> 代码位置：`/Users/chengzhy/.codex/worktrees/da43/verievolve/examples/comm_dsp_bench/dspgraph/`。

## 1. 一句话

给定一个**数学公式和系统指标**，LLM 写出一段**构造硬件的程序**；系统把程序编译成 Verilog，用一个**不了解实现内部的裁判**按公式打分，再把结果反馈给 LLM 继续改。数学变换（等价的和近似的）全部发生在 LLM 写的那段程序里。

## 2. 三个部分，各管各的

```
        ┌──────────────────────────────────────────────────────────────┐
        │ ① 规格（人写，一条链写一次）                                  │
        │    数学公式 + 指标门槛 + 测试信号                              │
        └───────────────┬──────────────────────────────────────────────┘
                        │ 公式、指标、原语说明、上一轮的反馈
                        ▼
        ┌──────────────────────────────────────────────────────────────┐
        │ ② LLM（通过 API 调用）                                        │
        │    输出：一段 Python 程序 build(g, spec)，用原语搭出整条链     │
        │    数学变换在这里做                                           │
        └───────────────┬──────────────────────────────────────────────┘
                        │ 程序
                        ▼
        ┌──────────────────────────────────────────────────────────────┐
        │ ③ 固定的系统（写一次，对所有链通用）                           │
        │    编译器：程序 → Verilog + 面积                               │
        │    裁判：仿真 Verilog，对照公式算 SNR 和纹波                   │
        │    诊断：不达标时确定性地定位原因                              │
        └───────────────┬──────────────────────────────────────────────┘
                        │ 是否达标、面积、失败原因
                        └──────────────► 回到 ②
```

### ① 规格：人写的唯一东西

以接收链为例，规格只有三样：

- **公式**：`y[m] = (h * (x[n] · e^{-j2π f_if n}))[m·R]`。意思是把中频信号搬到零频、低通滤波、抽取 R 倍。`h` 不指定，任何满足指标的低通都行。
- **指标**：通带纹波上限；系统 SNR 下限（等于理想接收机的 SNR 减去允许的实现损失，1.5–2.5 dB）；输入和输出位宽；总抽取倍率。
- **测试信号**：24 个通带内的复音作为期望信号，加上 3 个落在混叠频带里的强阻塞音。有 2 组用于搜索，另有 3 组阻塞音位置不同的留出场景，只在最后复验时用，LLM 和搜索都看不到。

规格里没有任何实现信息。换一条链（比如发射链、信道估计）就是换这三样。

### ② LLM：输入和输出

**输入**（每次调用）：

1. 上面的公式和指标。
2. 原语的使用说明（见下表）。
3. 当前最好的程序，以及最近几次尝试和它们的反馈。

**输出**：一段完整的 Python 程序。例如最直白的写法（照着公式逐字实现）：

```python
def build(g, spec):
    x = g.input()
    ph = g.counter(spec.fcw, 32)                      # 相位 = n·f_if
    addr = g.bits(ph, 31, 22)                         # 取高 10 位查表
    cos = g.lut(addr, [math.cos(2*math.pi*k/1024) for k in range(1024)], 16, 14)
    sin = g.lut(addr, [math.sin(2*math.pi*k/1024) for k in range(1024)], 16, 14)
    i = g.q(x * cos, 18, 16)                          # 混频
    q = g.q(-(x * sin), 18, 16)
    h = scipy.signal.remez(511, ...)                  # 一个大低通
    i = g.mac(list(zip(g.delay_line(i, 511), h)))     # 511 抽头直接型
    q = g.mac(list(zip(g.delay_line(q, 511), h)))
    g.output(g.q(g.decimate(i, 32), 16, 15), g.q(g.decimate(q, 32), 16, 15))
```

这个写法正确但面积巨大。LLM 的任务就是把它改好。

### 数学变换在哪里做

**全部在 LLM 写的程序里。** 系统不内置任何变换规则，也不内置任何算子。下面这些都是 LLM 自己要想到并写出来的：

| 变换 | 类型 | 在程序里怎么体现 |
|---|---|---|
| 先抽取再滤波（多相恒等式） | 等价 | 把 `decimate` 挪到 `mac` 前面 |
| 一个大滤波器拆成多级 | 近似 | 写多段 `delay_line` + `mac` + `decimate` |
| 用积分梳状代替第一级滤波（CIC） | 近似 | 用 `integrate`、`decimate`、相减搭出来 |
| 利用系数对称，先加后乘 | 等价 | 先 `tap[k] + tap[N-1-k]` 再进 `mac` |
| 半带滤波器（一半系数为零） | 近似 | 设计系数时让隔一个为零，零系数自动不生成硬件 |
| 四分之一波查表 | 等价 | 表只存 1/4，用 `bits` 和 `mux` 做镜像 |
| 截短位宽、少用系数位 | 近似 | 改 `q()` 的位宽、`mac` 的 `coef_bits` |
| 乘法器分时复用 | 微架构 | `mac(..., share=F)` |

"近似"的意思是输出和公式不完全相等，但误差在指标允许的范围内。是否允许由裁判说了算，不由规则说了算。

### ③ 固定的系统

**原语**（共 16 个，与具体算子无关）：

| 类别 | 原语 |
|---|---|
| 定点算术 | `add` `sub` `neg` `mul`（变量相乘）`scale`（乘常数，移位加实现）`shift` |
| 位宽控制 | `q`（舍入或截断，饱和或回绕） |
| 查表与选择 | `lut` `bits` `mux` `const` |
| 时序 | `reg`（流水）`delay_line`（样点延迟）`integrate`（累加）`decimate`（抽取）`counter` |
| 乘加 | `mac`（常系数乘加，可选分时复用） |

这里面没有 FIR、CIC、NCO、CORDIC。这些都是 LLM 用原语拼出来的。

**编译器**做三件事：

- 自动处理时钟周期对齐。LLM 只管样点级的数学，不用管哪一拍有效。
- 生成可综合的 Verilog。
- 按原语算出面积估计，并按 LLM 自己起的名字（`with g.scope("cic")`）分组。

**裁判**只看输入输出：

- 把测试信号送进 Verilog 仿真，拿到输出。
- 对照公式算 SNR（混叠、失真、量化噪声全部算作误差）和通带纹波。
- 它不知道也不关心里面是什么结构。所以手写的专家设计、传统搜索的结果、LLM 的程序，都用同一把尺子量。

**诊断**（不达标时）：

- 程序报错：返回错误类型和行号。
- 溢出：编译器在每个饱和点埋了计数器，报告哪一段溢出了多少次。
- SNR 不够：把所有位宽加宽 4 位重跑一次。如果达标了，说明是精度问题，再逐段加宽找出是哪一段；如果还不达标，说明是结构问题（滤波不够），加位宽没用。

这些原因都是重新跑出来的，不是猜的。这就是命题 3 里"经过验证的失败原因"。

## 3. 三个命题对应的实验

| 命题 | 比什么 | 判据 |
|---|---|---|
| 2. LLM 能找到满足约束的近似变换吗 | 从"照公式直写"的程序出发，LLM 改出来的设计，对比专家手写的教科书设计 | 达标前提下的综合面积；LLM 用了哪些变换 |
| 3. 验证过的失败原因有用吗 | 同一个 LLM、同样的调用次数，反馈分三档：只给达标与否和面积；给全部指标数值；再加上面的诊断 | 相同预算下的最小达标面积，首次达标所需次数 |
| 1. 联合优于分阶段吗 | 同一组可选项，一种是先定结构、再调精度、最后选复用；另一种是三者同时搜 | 达标前提下的综合面积 |

每个比较都在 6 个开发规格上跑多个种子，方法冻结后再到 6 个留出规格上复验。

| 部分 | 状态 |
|---|---|
| 规格、测试信号、裁判 | 已实现。时延自动搜索；SNR 门槛 = 理想接收机 − 1.5~2.5 dB |
| 原语与编译器 `dspgraph/sdf.py` | 已实现。每个原语同时给出 Verilog、逐位整数值和面积；超过 62 位自动改用任意精度整数（上限 128 位） |
| 工程检查 | 多相、分时复用、CIC 回绕、75 位宽设计的 RTL 与整数语义逐位零失配；回归测试 `tests/test_dspgraph.py` |

| LLM 搜索 | 用仓库里的 OpenEvolve 做 diff 式进化，起点是"照公式直写"程序（已达标），`dspgraph/oe_eval.py` 负责评价 |
| 专家对照 | `dspgraph/template.py`：教科书 NCO→CIC→半带→补偿 FIR 的参数化程序，供命题 1 与命题 2 对照 |

### 试点的教训（用来决定 harness 怎么做）

- **每次让 LLM 写一个完整新程序**：80 次调用只有 9 次达标；加编译修复和探针后反而只有 1 次。
- **改成 OpenEvolve 式**（种群 + 小幅 diff + 选择）：种群中约 55–65% 的程序达标，面积持续下降。
- **思考模式不可用**：DeepSeek 开启思考后，2 万 token 都花在推理上，没有输出代码。
- **62 位上限是实现带来的假约束**：它曾占非法程序的一半以上，现已去掉。

### 首批正式结果（200 次迭代，单种子）

| 规格 | 直写起点 | LLM 最优 | 专家模板·分阶段(中位) | 专家模板·联合(中位) |
|---|---|---|---|---|
| r16 窄带 | 1,874k | 136k | 59k | 73k |
| r16 宽带 | 2,440k | 269k | 370k | 258k |
| r32 宽带 | 3,483k | 487k | 563k | 370k |

单位为代理面积，最终以真实综合复核。LLM 自己找到的变换：四分之一波查表镜像、对称预加、多级抽取（8×2×2）、缩短位宽、乘法器分时复用。它没有找到 CIC、半带和多相。

## 5. 之前走偏的地方

- 最初让 LLM 在几十个预先列好的设计里挑，或者只调参数。这种空间可以穷举，LLM 不可能比枚举好。
- 中间一版我手写了 NCO、CIC、FIR 模块，LLM 仍然只是选参数，变换是我做的而不是 LLM。
- 现在的架构把"实现"整个交给 LLM，系统只保留和算子无关的原语、编译器和裁判。

## 6. 已知风险

- 一次性写程序的成功率很低，需要进化式小步修改；模型目前只用 `deepseek-flash`。
- 照公式直写的起点设计有几百个抽头，仿真可能很慢。
- 面积在搜索时用估计值，只对最终设计做真实综合。估计值和综合值的一致性还没有校准。
- 本机没有静态时序分析工具，只能报告面积，不能报告时序收敛。
