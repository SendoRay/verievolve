## 1. Problem Anchor

- **底层问题**：在固定通信 DSP 数学/数据流规格与端到端数值契约下，联合选择算法分解、近似原语和定点化，检验它相对强基线能否在相同提案预算内找到更好的质量—真实综合面积折中。
- **必须检验的瓶颈**：局部指标筛选、先定结构再调字长、按可加局部成本提取，是否在当前多速率部署契约中丢失有工程意义的候选；现有机制反例不等于已证明设计损失。
- **非目标**：重证已知谱传播原理、预设 LLM 必要、把 typed IR 或 e-graph 本身包装成创新、开发通用 HLS、扩展第二条链来寻找阳性结果。
- **约束**：沿用冻结契约与既有结果；不事后调整阈值、候选池或重选 witness；成本来自真实综合；所有提案尝试均计预算；保持强基线公平。
- **成功条件**：通过实现与评价可信性 gate 后，按预注册标准在 held-out 上验证有限预算前沿相对强基线有工程余量且多种子统计支持；LLM 独特收益需要后续独立交互检验。

## 2. 真正要做什么

不是再搭一个“LLM 生成硬件”的平台，而是检验：**联合改变结构与定点化，是否能在既定通信任务下改善实际硬件选择。**

最小载体仍是 NCO→复乘→FIR/抽取。NCO 用 LUT、CORDIC 还是组合结构，FIR 用直接型还是多相，以及乘积、累加与输出的量化选择，必须进入同一个系统质量与硬件成本比较。

研究对象不是组件数，而是一项可复现、可归因的设计收益：哪几项选择需要一起改变，哪种受限流程没有找到它，得到的优势是否超过工程阈值且可在独立运行中重复。

## 4. 一个主贡献候选，一个支持项

**主贡献候选**：契约驱动的联合硬件设计方法及其相对明确强基线的有限预算收益。

**支持项**：从统一的候选结构建立可验证的数值评价与 RTL 实现路径，使不同搜索策略公平比较。

本地近邻记录表明，系统质量约束 WLO、近似算子联合选择、精确重写、近似 lowering、GP 与综合反馈等组成能力已有先例。不能把它们拼接后直接声称新颖；Chassis 也不应被描述为完全不做整候选精度评价。

依据：`thesis/PROPOSAL_v1.md:24-31`、`thesis/NEIGHBOR_MATRIX_HLS_RTL.md:108-136`。本轮不是完整查新。

## 5. 先解决比较命题的逻辑缺口

`thesis/SEARCH_PROTOCOL_v1.md:17-19` 的表述涉及强通用搜索，`:217-222` 的 S1 判据则直接针对 staged WLO 与 cost-first 前沿。两者并不等价。

必须分开三个问题：

1. **表示/可达集合**：是否允许真实组合，而不是仅选择已登记模板？
2. **决策方式与反馈**：允许结构—量化联合修改，相比提前锁定，是否有收益？系统风险反馈相比其他反馈带来了什么？
3. **提议算法**：同语言、同动作、同预算下，谁更高效地找到好点？

**推荐口径（尚未修改原协议）**：S 阶段优先检验第 2 项，用同一个强非 LLM 引擎控制搜索算法变量，比较联合修改与分阶段锁定；同时保留完整语言的强 GP/beam 作为算法参照。若 GP 本身就是联合方法的执行器，不声称其击败“同配置 GP”。

如果要进一步声称优于同语言强 GP/beam，就必须先明确额外的方法机制是什么，不能以换上 LLM 或扩大我方语言作为隐含答案。

对固定的合法实现集合和评价函数，真实 Pareto 集合不因搜索器而改变。论文比较的是**相同预算发现的前沿**，不能混同于扩大实现空间带来的可达边界变化。

## 6. 最小机制，不继续扩平台

数学与部署规格 → 公共 typed IR/动作 → 合法性检查 → 公共 bit-true 与 RTL lowering → 整链质量和真实综合面积 → 非支配 archive → 下一次联合提案。

- 只保留真实需要的组合构造器与量化选择，暂不追求任意 RTL 或无限递归表达。
- 精确实数分解与近似原语分层；模型—RTL 一致不意味着对实数目标无误差。
- 起步优先直接使用 full-chain bit-true 质量评价。只有实际成本需要且新结构通过校验，才考虑线性模型代理，避免先扩评价模型。
- 旧 E1 的固定下游适用范围不能自动迁移；旧 NCO-only 面积不能代替可变 FIR 的全链面积。
- 没有冻结时序、功耗或物理实现流程，就只报告指定综合流程下的面积，不称完整 PPA 优势。
- 同一语义候选的实现、系数、工具链、场景与评价版本要可追溯；缓存节省墙钟时间，不返还重复或失败提案的预算。

## 7. 最多三个核心验证块

### 7.1 比较资格：候选是否真的可比

用固定小开发用例验证公共表示、数值语义、RTL 握手、质量定义、真实成本和产物追溯。具体缺口由阶段 A 工程审计提供。

**反证**：模型与 RTL 不一致、改变外部任务换面积、仅我方拥有组合表达能力、成本对象不同，或失败提案免费。

**结论边界**：通过仅代表具备比较资格；未完成是工程 gate 未过，不是实证 S0。临时 smoke 不能写成正式 R4 面积证据。

### 7.2 核心 S 检验：不用 LLM，联合设计是否有价值

- 固定图 WLO 应允许使用系统级质量约束，不能只做一个弱局部指标版本代表整个 WLO 类。
- 比较联合修改与分阶段锁定时，尽量固定同一引擎、初始条件和质量评价，明确动作限制是实验变量。
- cost-first 基线与完整组合语言的 GP/beam 参照各回答不同问题；不能互相替代。枚举切片只检查实现与可达性，随机不是唯一强对手。
- 正式预算、种子、工程阈值、统计方法与最终输出选择规则须事前确认。搜索、选择和调参不读取 held-out 反馈；已被历史研究查看过的 held-out 必须如实称为历史留出验证，不能声称全新盲测，也不能擅自更换冻结场景。
- 用全链 bit-true 和真实全链综合面积终考，分析稳定发现的前沿，以及具体共同变化的结构/定点选择。

**反证**：同等表达能力或强基线补齐后优势消失；仅单种子偶然好点；只胜过弱筛选；质量终考不通过；未达到确认后的工程/统计标准。

只有完成有效的正式检验后，才能据规则判 S0/S1。

### 7.3 条件 L 检验：LLM 是否提供增量

仅在 S1 后，做 LLM/强非 LLM × numerical/satisfaction 对照，共用表示、动作、初态、预算和评价；报告 token、调用与墙钟成本。

两种反馈来自同一链级质量，检验的是反馈信息量，不是“局部评价对系统评价”。正交互也不自动等于 LLM 绝对表现更好或不可替代。

**反证**：无交互增益、绝对性能没有增量或代价不支持效用。撤去相应 LLM 独特性主张，允许其仅作为可替换提案器。诊断模块和第二条链都不前置。

## 8. 实施顺序与立即取舍

1. **先明确 S 的比较命题**，不要先写搜索器再决定自己战胜了谁。
2. **利用只读审计定义最小开发闭环**，只补直接阻塞比较的接口与可信性问题；实施前另给代码计划。
3. **开发期固定小用例验证接入，再完成真实综合 gate**，不把开发 smoke 当研究结果。
4. **非 LLM pilot 校准预算与方差；正式规则确认后做 S 实验**，不借 pilot 调成功阈值或挑有利任务。
5. **仅在 S1 后做 L；进一步扩展更晚决定。**

暂不做：旧池挑反转、为保新理论制造饱和、扩大算子目录、搭通用 e-graph、增加代理/诊断堆栈、调用真实 LLM 搜索、提前写阳性论文结论。

## 9. 剩余风险与结论

最大的风险是系统能跑，但仍只是已有能力的工程整合。即便联合 GP 胜过分阶段流程，也不自动证明新搜索算法或足够学术新颖性；需要与近邻能力对齐、解释可归因增量并保留失效边界。

当前的实施 NMSE 不等于完整通信 EVM/BER 保证；单条链、有限语法与离散栅格不能外推为通用通信硬件优势。

**结论：继续检验方向，但以最小可信闭环取得一次能决定继续或停止的设计比较为近期目标，而不是继续扩充“解析评价＋LLM”平台。**
