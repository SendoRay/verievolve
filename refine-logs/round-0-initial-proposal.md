## Problem Anchor

- **底层问题**：在固定通信 DSP 数学/数据流规格与端到端数值契约下，联合选择算法分解、近似原语和定点化，检验它相对强基线能否在相同提案预算内找到更好的质量—真实综合面积折中。
- **必须检验的瓶颈**：局部指标筛选、先定结构再调字长、按可加局部成本提取，是否在当前多速率部署契约中丢失有工程意义的候选；现有机制反例不等于已证明设计损失。
- **非目标**：重证已知谱传播原理、预设 LLM 必要、把 typed IR 或 e-graph 本身包装成创新、开发通用 HLS、扩展第二条链来寻找阳性结果。
- **约束**：沿用冻结契约与既有结果；不事后调整阈值、候选池或重选 witness；成本来自真实综合；所有提案尝试均计预算；保持强基线公平。
- **成功条件**：通过实现与评价可信性 gate 后，按预注册标准在 held-out 上验证有限预算前沿相对强基线有工程余量且多种子统计支持；LLM 独特收益需要后续独立交互检验。

## 一条主线，而不是三个并列项目

**待证主张**：组合结构与定点化的联合选择，使用实际部署契约的整链数值质量反馈，能在相同预算内找到强基线未找到的质量—面积折中。

支持项是使同一候选同时得到可信数值行为与真实硬件成本的统一表示/评价接口。

LLM 暂作为后续可替换提案器。只有先证明这个搜索问题值得做，才进一步检验 LLM 是否更擅长提出结构组合，不能倒过来为 LLM 寻找理由。

## 最小机制

数学/部署规格 → 同一 typed IR 与公共动作 → 同一 bit-true 和 RTL lowering → 同一契约评价与真实综合 → 有限预算 archive。

结构身份、实现身份和评价身份不能混为一个 hash。缓存只能节省时间，不改变候选尝试预算。详细接口风险由并行的阶段 A 只读审计提供，不把这份模块列表当作学术贡献。

## 最多三个验证块

### 1. 比较是否可信

以固定小型开发用例验证同一 IR 的数值行为、RTL 行为、握手、质量定义、成本口径和结果回显；不拿 smoke 结果替代正式 R4，不运行正式 77 场景 truth。

### 2. 联合数值选择是否值得做（S）

先用非 LLM 搜索。保留固定结构 WLO、cost-first extraction，以及同语言的 GP/beam/MCTS 强基线；清楚区分表示/可达空间、反馈与搜索器三个变量，不能让它们同时变化后把全部增益归给一个机制。

同一空间、契约和成本下的真实 Pareto 集合不因搜索器改变；比较的是有限预算发现的前沿，而不是声称算法改变了物理最优集合。切片枚举只用于检查实现，不能作为开放空间的主结果。

### 3. LLM 是否有独立增量（L）

仅在 S1 后运行 proposer × feedback 的 2×2；LLM 与强非 LLM 共用 IR、动作、预算、评价与选择规则。LLM 的必要性不能由系统误差的复杂性或单独的 LLM 数值臂优于 Boolean 臂推出。
